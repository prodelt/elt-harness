# elt — вход в код под харнесом

Первой строкой любой работы объявить режим: `elt → <режим>`.

Плагин даёт четыре входа. `/elt` — этот файл; остальные три — отдельные команды.

| хочу | вход |
| --- | --- |
| закрыть слайс под гейтом | `/elt` |
| прочитать свои изменения пятью линзами | `/elt-verify` |
| записать расхождение вердикта с реальностью | `/elt-defects` |
| понять, жив ли харнес | `/elt-doctor` |

Плюс два хука, которые ставятся вместе с плагином и работают без вызова: `SessionStart` даёт
сводку по проекту (ветка, режим `verify`, план, очередь ревью), `Stop` не даёт закончить
сессию с незакоммиченной правкой в ELT-проекте. Код — `bin/session-start.js` и
`bin/session-stop.js`, манифест — `hooks/hooks.json`. Установка и паритет Codex/Gemini
описаны в `docs/INSTALL.md`.

## Режимы

0. **Большая новая цель без плана** — `specs/NNN-name/spec.md` + `tasks.md`, показать
   пользователю, дождаться явного «утверждаю», затем `elt spec approve --spec specs/NNN-name`
   (отдельный узкий коммит с трейлерами `Spec-Approved:` / `Spec-Hash:` / `Tasks-Hash:`;
   оракул и судья на нём не гоняются). Дальше режим 1.
1. **Есть открытые задачи** в `specs/*/tasks.md` — вести слайсы по плану.
2. **Один вертикальный срез без плана** — микрослайс с наименьшим релевантным тестом.
3. **Голое `/elt`, «продолжи», «что дальше»** — восстановить контекст и предложить ОДИН
   конкретный следующий шаг, а не список вариантов.

Тривиальную правку церемонией не обкладывать: сделать, запустить наименьшую проверку,
показать доказательство.

## Восстановление контекста

`elt status` → свежайший `.planning/CHECKPOINT-*.md` (секции `Resume` / `ДАЛЬШЕ`) → начало
`.planning/STATE.md`. Без `--spec` берётся САМЫЙ НОВЫЙ план, даже закрытый: старые открытые
планы не воскресают сами. Для старого плана `--spec specs/NNN-name` обязателен.

## Роли

Писатель и судья — разные. Писатель не судит свою работу.

- **Писатель.** По умолчанию код пишет текущая поверхность. Если пользователь просит отдать
  написание Antigravity — вызывать `agy` контрактом из
  `specs/019-elt-v5-phases-2-5/writer-prompt-v3.md`. Порядок секций промпта (разведка →
  решение → запреты → заявка) обязателен и держится тестом: писатель, прочитавший запреты
  раньше, чем разобрался в зоне, экономит на разведке и правит наугад. Antigravity не
  загружает скилл сам и врёт, что загрузил, — строка «прочитай
  `~\.gemini\skills\elt\SKILL.md`» в промпте обязательна.
- **Судья.** Ровно один, текущей поверхности. Второго раунда судьи нет.

## Одна дверь: `elt run`

Маршрут больше не надо помнить. Состояние прогона живёт в append-only журнале
`.git/elt/graph-journal.jsonl`, а следующий законный шаг вычисляется из канонического графа:

```
node "${CLAUDE_PLUGIN_ROOT}/tools/elt.js" run           # узел + следующий шаг словами
node "${CLAUDE_PLUGIN_ROOT}/tools/elt.js" run --json    # то же машинно (это же зовёт SessionStart)
node "${CLAUDE_PLUGIN_ROOT}/tools/elt.js" advance --event ready --guard task-dependencies-closed
```

`advance` fail-closed: недоказанный guard или незаконное событие дают ненулевой выход и
НИ ОДНОЙ строки в журнале. Низкоуровневые `oracle`/`judge`/`commit` остались диагностическим
фасадом и пишут те же события — поэтому состояние переживает compact и перезапуск сессии.

`elt cutover` переключает авторитет с checkbox на журнал ровно один раз и только когда снимок
миграции чист: любая неоднозначность легаси-эпохи блокирует переключение и ничего не пишет.
До cutover действует эпоха `legacy-v1` — авторитет у `tasks.md`, approval-трейлеров и run-log.

## Цепочка гейта — одним заходом, без записи в дерево между шагами

```
node "${CLAUDE_PLUGIN_ROOT}/tools/elt.js" oracle --full
node "${CLAUDE_PLUGIN_ROOT}/tools/elt.js" judge run --task T001 --spec specs/NNN-name
node "${CLAUDE_PLUGIN_ROOT}/tools/elt.js" commit --task T001 --spec specs/NNN-name --skip-oracle -m "feat: описание"
```

Любая запись в дерево между шагами даёт `stale-tree`, перегон оракула внутри `commit` —
`stale-oracle`; поэтому `--skip-oracle` в цепочке всегда.

Батч из 2–4 близких задач ОДНОГО плана: `--task T001,T002,T003` во всех трёх командах.
Не батчить разные спеки, рискованные архитектурные правки и зависимые задачи.

**Правка вне задач батча выносится отдельным слайсом.** Судья ловит её как scope creep и
блокирует ВЕСЬ батч, а не одну строку.

## Вердикты

- `pass` — коммитить;
- `block` — не коммитить, чинить причину или парковать задачу;
- `inconclusive` — коммит с записью в `.harness/review-queue.jsonl`, без второго раунда.

Красный оракул — максимум две узкие попытки починить причину. Тесты не удалять и не
ослаблять. Дальше остановиться без коммита и показать доказательство.

## Что харнес обещает

`Done` означает одновременно четыре вещи, не три:

1. механический оракул exit 0;
2. smoke exit 0, если он настроен;
3. ровно один судья — `pass` или `inconclusive`;
4. `elt commit` создал коммит и запись в run-log.

Ручной `git commit` не запрещён технически, но он не попадает в run-log — а доля работы,
прошедшей через харнес, измеряется именно по нему. Этот замер и есть единственный честный
ответ на вопрос «работает ли система»: в репозитории-разработчике 62,0% (49 из 79 коммитов)
против базлайна 18,6%.

## Владения харнеса не судятся

`tasks.md`, `.harness/**`, `run-log.jsonl`, `.planning/CHECKPOINT-*-auto.md`,
`tools/judge-bench/cases-ingested.json`, `package-lock.json` и прочие сгенерированные
артефакты пишет сам харнес. Единый список — `tools/harness-files.js`, одна функция
`isHarnessOwned`. Второго списка заводить нельзя: именно два разошедшихся списка породили
дефекты D9, D15 и D19, а с ними — сигнал/шум блокирующих вердиктов 1:7.

## Ревью — пять линз, потом отсечка

Линзы (`agents/review-*.md`) запускаются ПАРАЛЛЕЛЬНО и не знают оценок друг друга. Оценщик
уверенности (`agents/confidence-scorer.md`, модель `claude-haiku-4-5-20251001`) ставит
0–100, отсечка 80. Порядок обязателен: оценщик, увиденный линзами заранее, схлопывает пять
независимых взглядов в один.

## Подпись спеки

Живёт в трейлерах коммита, не в файле: `approval.json` снят спекой 018, разбор трейлеров
делегирован самому git (`%(trailers:key=...)`) — свой построчный regex делал подпись
подделываемой обычным текстом коммита. Изменилось содержание спеки или текст задач — подпись
нужна заново. Молчаливое повторное подписание допустимо только после чистого `[ ]` → `[X]`,
который сделал сам `elt commit`.

## Планы

Для большой цели создаются только два файла: `spec.md` (Проблема, Решение, User stories,
Критерии приёмки, Риски, Вне scope) и `tasks.md` (атомарные строки `- [ ] **T001** ...`,
каждая проверяется оракулом или коротким тестом). `plan.md` не создавать: runtime его не
читает.

## Линзы, а не вторые control plane

баг → `diagnose`; UI/E2E → `qa` + браузер; дизайн → `design-studio`; внешняя библиотека →
`ctx7` до кода; структура кода → `codegraph_context` перед чтением файлов целиком.

Линза помогает ВНУТРИ слайса. Оракул, один судья и коммит всегда остаются в `elt`.
