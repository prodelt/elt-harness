① Идея в одну строку

Agent = Model + Harness. Качество — не «старайся лучше», а guide (направляет ДО) + sensor (ловит ПОСЛЕ) + блокирующий gate (стоп в нужный момент) + steering (растёт от повторов боли).

Система — это тонкий слой-вход поверх готового, а не новая платформа. Главный закон — анти-AMOS: ничего не инжектится каждый ход, конфиг живёт per-project, всё on-demand, «Done» — только с доказательством. Авто-нуджей и фоновых циклов нет: дисциплина на тебе, инструменты — под рукой.

Почему так: прежний толстый слой (AMOS — авто-хуки, advisory-спам, авто-loop) был снят 2026-06-18, потому что мешал больше, чем помогал. Эта методичка описывает то, что осталось и работает.

② Из чего состоит система

Пять слоёв, от тонкого глобального к ритуалу проекта. Каждый — самостоятелен.

Слой 0 · Глобально (тонко) always-on, но дёшево
Один хук PreCompact (briefing при компакте). Плагины: ponytail (анти-оверинжиниринг, каждый ответ), claude-mem (память, worker :37777). MCP: codegraph (структурный поиск кода), mem-search, law. Ничего не инжектится per-turn кроме ponytail.
Слой 1 · Карта — PLAYBOOK.md
Не знаешь, что делать с задачей? Читаешь сверху вниз, останавливаешься на первой подходящей строке. Точка входа в систему, если непонятно.
Слой 2 · Роутер — /pipeline и /elt-code
/pipeline классифицирует задачу (TRIVIAL/MEDIUM/BUG/ARCH/COMPLEX/RESEARCH) → маршрут + бюджет скилов. /elt-code — единая дверь в кодинг: выбор интента ДО классификации сложности (они ортогональны).
Слой 3 · Ритуал — /project-bootstrap
Делает проект эталонным за один заход: AI-доки + харнесс с зубами (/harness-method) + codegraph-индекс + память проекта + привычка Context7. Идемпотентно.
Слой 4 · Метод — /harness-method
Fowler-харнесс per-project: guide (constitution.md) → sensor → блокирующий gate → steering. Церемония растёт с необратимостью: прод → тяжёлый gate, черновик → лёгкий guide.

Память — что где

Долгая (проект)

constitution.md/spec.md + CLAUDE.md + .planning/ + git

Кросс-сессия

Сессия

/checkpoint вручную при смене контекста; PreCompact пишет briefing на компакте

③ /elt-code — режим A (собран и доказан)

Тонкий диспетчер поверх существующих скилов. Сам код не реализует — классифицирует интент, роутит, и на код-задачах ставит судью-гейт последним перед «done». Не заменяет /pipeline — оборачивает его.

Судья-гейт — сердце A

Не ревьюер (находит проблемы), а судья (ставит вердикт по рубрике, измеримо). Отдельный субагент (Sonnet дефолт, Opus на COMPLEX/высоких ставках), не self-judge. Последний гейт перед «done».

Твёрдый пол БЛОКИРУЕТ

H0 closeout прошёл (тесты/линт/секреты) · H1 спека реализована (ровно то, не больше) · H2 нет оверинжиниринга (ponytail-audit чист)

Мягкое качество СОВЕТ 1-5

S1 читаемость · S2 структура · S3 консистентность · S4 качество тестов. Логируется, не блокирует.

Шов A→B: каждый вердикт пишется строкой judge_verdict в session-ledger.jsonl. Накопленные вердикты = eval-корпус для режима B.

④ B — eval-флайвил (v1 линза собрана 2026-06-20)

Система измеряет себя на данных, что копит A. Это линза, не маховик — on-demand отчёт, который читаешь рукой. Инструмент: node tools/update-judge-verdicts-index.js.

(a) Линза ЕСТЬ

Здоровье судьи (дисперсия/перекос осей, флаг вырождения) + тренд качества per-project + recall-крючок. Метит доверие к цифре (n+разброс); вырождение судьи гейтит доверие к метрикам работы.

(b) Советник ПОТОМ

Предлагает правки только судьи (рубрика/модель), человек применяет руками. Молчит, пока корпус не созрел.

(c) Автопетля ВЫЧЕРКНУТА

Сам правит — запрещено. Открывается только через 4 «ворота» (доказанный b + held-out + auto-rollback + версии). Урок AMOS: петли убили не петли, а петли без ворот.

Как пользоваться: B растёт сам, от твоей обычной работы. Каждый MEDIUM+ прогон через /elt-code даёт вердикт → корпус копится. Периодически запускай линзу и смотри: не штампует ли судья, какая ось проседает. Поймал реальный промах судьи → впиши строку judge_miss (recall-крючок ждёт). Спека: .planning/ELT-CODE-B-DESIGN.md.

⑤ Рабочий цикл — золотой путь

Это и есть «по методичке»: садишься за код-задачу — идёшь по шагам. Лёгкие задачи пропускают шаги (церемония по сложности).

  1. Дверь: /elt-code "что делаем" (или голый /elt-code → меню из 6 интентов).
  2. Классификация: /pipeline определит сложность и маршрут. TRIVIAL → просто делай, без церемоний.
  3. Спека (фича, MEDIUM+): spec-kit → spec.md = контракт ДО кода (уход от вайбкодинга).
  4. Доки либы: ctx7 перед кодом с внешней библиотекой (актуальные доки on-demand).
  5. План: /architect-first на развилках — инварианты до кода. grill-me если план сырой.
  6. Сборка: tdd (red-green) / sprint (слайсы с verify). codegraph_context ПЕРЕД чтением файлов.
  7. Sensor: inline-review сразу после юнита работы.
  8. СУДЬЯ: H0-H2 (блок) + S1-S4 (совет). BLOCK → доработка → пересуд. PASS → закрывать.
  9. Closeout: lint/test/типы зелёные (это и есть H0). security-best-practices если смежно.
  10. Ship: ship/git-flow — одна задача = одна ветка, PR с Test plan.
  11. Снимок: /checkpoint при смене контекста; вердикт уже в ledger (кормит B).

Бюджет скилов по умолчанию: 1 оркестратор (pipeline) + 1 доменный + 1 верификатор. Больше — только если задача явно мульти-доменная или verify вскрыл риск (назови причину).

⑦ Перила — красные линии (анти-AMOS)

1. No per-turn injection. Ничего не грузится в контекст каждый ход (кроме ponytail). Всё on-demand.
2. Per-project конфиг. Рубрики/спеки/память живут в репо проекта, ездят с ним. Не глобально.
3. Enforce, не nag. Гейт либо блокирует измеримо, либо его нет. Никаких advisory-нуджей «подумай бы».
4. «Done» только с proof. [x] ставится лишь после вывода build/test/lint, не «готово».
5. Никакого авто-самоулучшения. Система не правит себя сама. Человек на файле — гейт любой правки.

Привычки экономии (уже включены, просто соблюдай)

codegraph до Read · ponytail активен · claude-mem пассивно · доки on-demand (ctx7, не always-on MCP) · субагенты на haiku (тяжёлое суждение — главному) · команда агентов только при реально параллельной независимой работе (>2 агента правят код → обязателен verify-шаг).

⑨ Оценка: насколько система мощна — и уровень Anthropic

7.5
/ 10

Как персональная инженерная методология поверх Claude Code — верхний дециль.

Сильный дизайн и редкий вкус; но недодоказана на потоке, single-user, держится на ручной дисциплине. Это честная оценка, не лесть.

По осям (честно)

Архитектурный вкус (анти-AMOS, сняли лишнее, on-demand)9
Измеримость / eval-seam (судья + ledger + линза)8
Портируемость (файлы-источник правды, кросс-CLI)8
Доказанность на потоке (корпус n=2, recall не валидирован)5
Масштаб / надёжность без человека (намеренно ручное)5

Что делает её мощной

Вкус снести лишнее

Большинство строят больше. Снять собственный over-engineered слой (AMOS) и оставить тонкое — редкий инженерный вкус.

Eval-driven, не «вайб»

Судья ставит измеримый вердикт, лог = корпус, линза измеряет самого судью. Это продуктовое мышление, а не набор промптов.

Рекурсия

Система строит свои части через себя (B собрана через /elt-code + судью, дав вердикт в корпус, который B и анализирует).

Принципы, а не фичи

Анти-AMOS перила выучены на реальном провале и держат дизайн от рецидива. Гейты вместо нуджей.

Что ограничивает (и куда расти)

  • Корпус мал (n=2). Eval-флайвил пока теоретически здоров — сигнал слаб, пока не накопится поток. лечится временем
  • Recall судьи не доказан. Знаем, что судья консистентен — не знаем, что он прав. Крючок judge_miss ждёт дисциплины.
  • Держится на человеке. Гейтов-автоматов нет (намеренно). Сильно от тебя зависит — это плюс по философии, минус по «мощи без оператора».
  • Single-user, Windows-specific. На команду/CI не обкатано.

Уровень Anthropic — честный ответ

Нужно разделить два класса. Anthropic строит инструмент — модели + сам Claude Code (харнесс-инфра) + продуктовые eval-пайплайны на масштабе команд и CI. Твоя система — методология использования этого инструмента, single-user, поверх их харнесса. Это другой класс, не «их инфра-уровень» — сравнивать масштаб некорректно.

Но по философии — да, совпадает с тем, как думает Anthropic: harness > prompting, eval-driven, вкус против оверинжиниринга, «снести лишнее важнее, чем добавить». Как персональная методология поверх Claude Code она в верхнем дециле того, что вообще строят поверх агентов. Чего не хватает до «их уровня по сути»: масштаб данных (их eval'ы — тысячи примеров, у тебя 2) и автоматизированная валидация (held-out, не глаз человека). Дизайн готов туда расти — ворота к этому уже прописаны. Сейчас: сильная личная система с правильными костями, не продукт их масштаба.
