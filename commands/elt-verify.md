## Контекст

- Механический гейт L0: !`node "${CLAUDE_PLUGIN_ROOT}/bin/l0.js"`
- Статус дерева: !`git status --porcelain`

## Задача

Аргументы: `$ARGUMENTS` (пусто — ревьюим незакоммиченные изменения; иначе — названную ревизию
или диапазон).

Ревью идёт по официальному рецепту: **пять линз параллельно, потом отсечка по уверенности.**
Порядок обязателен — линзы не должны знать оценок друг друга, иначе они сговариваются на
общем ложном срабатывании.

### 1. Дифф

Собери дифф один раз и передай его линзам как контекст, а не заставляй каждую собирать заново.

### 2. Пять линз — ОДНИМ сообщением, параллельно

Запусти пять субагентов одним блоком вызовов (параллельно, не по очереди):

| линза | что ищет |
| --- | --- |
| `review-bugs` | явные баги в самих изменённых строках |
| `review-claude-md` | нарушения правил проекта из `CLAUDE.md` / `AGENTS.md` |
| `review-code-comments` | комментарии, разошедшиеся с кодом, который они описывают |
| `review-history` | конфликт с историей файла — правка отменяет осознанное прошлое решение |
| `review-prior-comments` | повтор того, на что уже указывали в прошлых ревью |

Каждая обязана вернуть массив находок вида
`{file, line, summary, failure_scenario, confidence}` и **ничего не писать** — линзы читают.

### 3. Отсечка по уверенности

Собери все находки и прогони их через оценщик `confidence-scorer` (модель
`claude-haiku-4-5-20251001`). Отсечка — **80**: находка ниже 80 не показывается пользователю.

Известные ложные срабатывания оценщик знает поимённо; их список — в
`${CLAUDE_PLUGIN_ROOT}/tools/review-confidence.js` (`KNOWN_FALSE_POSITIVES`). Не пересказывай
его в промпте линзы: список живёт в одном месте намеренно, копия разойдётся.

### 4. Владения харнеса не судятся

Файлы, которые пишет сам харнес, из ревью исключаются целиком — по
`${CLAUDE_PLUGIN_ROOT}/tools/harness-files.js` (`isIgnoredForReview`). Это `tasks.md`,
`.harness/**`, `run-log.jsonl`, авточекпоинты, `package-lock.json` и прочие сгенерированные
артефакты. Упрёк за файл, который харнес сгенерировал сам, — ровно тот шум, из-за которого
вердикты перестают читать (замер: сигнал/шум 1:7).

### 5. Вывод

Покажи выжившие находки, отсортированные по убыванию уверенности: файл, строка, одна фраза
сути, один конкретный сценарий отказа. Если не выжило ничего — так и скажи одной строкой,
не расписывая, что именно проверялось.

Каждое ложное срабатывание, которое ты заметил сам, запиши в журнал:
`node "${CLAUDE_PLUGIN_ROOT}/bin/ledger.js" record --kind false-positive --rule <имя правила> --note "<что именно>"`.
