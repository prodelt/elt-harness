# D0 — поймал бы smoke-контракт три уехавших регресса?

Слайс T001 спеки `specs/010-judge-delivery`. Порог объявлен ДО разведки (Р4 спеки):
**N≥2 → smoke-слайсы дописываются в 010; N≤1 → отдельная спека 011.**

**Определение smoke-контракта** (то, что оценивалось): одна команда в `harness.json`, которая
собирает приложение в его обычной dev-конфигурации и прогоняет 1–2 живых сценария против
реальных внешних сервисов, с ассертом на наблюдаемый результат. Не браузерный E2E-фреймворк.

**Итог: N=2**

| # | регресс | поймал бы smoke |
|---|---|---|
| 1 | doc2md-tauri, «ocr missing» (27.07) | **нет** |
| 2 | doc2md-tauri, «перестало считать токены» (29.07) | **да** |
| 3 | Route_API_1C, «визиком не участвует» (27.07) | **да** |

## Регресс 1 — doc2md-tauri: «ты поломал… ocr missing» (27.07)

**Симптом.** Релизные `.exe` 0.1.0–0.1.2 ехали юзеру с «OCR not configured».

**Коммит.** Фикс — `191c512` «fix(ci): валити реліз на порожньому OCR-секреті + bump 0.1.3»
(`.github/workflows/release.yml`). Вносящего коммита нет: дефект существовал с первого релиза.

**Причина (из тела фикса).** Секреты `GEMINI_API_KEY`/`OPENAI_API` в репозитории существовали,
но были пустыми. `build.rs` вшивал `None`, ни один шаг CI не краснел.

**Вердикт: НЕТ.** Дефект живёт исключительно в release-конфигурации CI. Smoke по определению
собирает dev-сборку на машине разработчика, где `.env` заполнен, — он был бы зелёным на всех
трёх сломанных релизах. Ловится тем, чем и починили: контрактом на непустоту секрета в
release-пайплайне. Это другой класс проверки, не «живой сценарий».

## Регресс 2 — doc2md-tauri: «снова перестало считать токены» (29.07)

**Симптом.** Счётчик токенов всегда 0.

**Коммит.** Фикс — `e939955` «fix: лічильник токенів завжди 0 — Gemini Interactions віддає usage
іншою формою» (`src-tauri/src/converters/ocr.rs`, +40). Внёс — `216e364` «feat: T004,T005,T006
Живий лічильник витрат».

**Причина.** Реальный Gemini Interactions отдаёт `usage` в форме, отличной от той, на которую
рассчитан парсер. Юнит-тесты со стабом старой формы зелёные — расхождение существует только
против живого API.

**Живой пруф (не рассуждение — реальный HTTP-вызов).** Скрипт
`.planning/d0-proof-scripts/d0-regression2-live.js` (`node .planning/d0-proof-scripts/d0-regression2-live.js`,
нужен `.env` с `GEMINI_API_KEY` в `doc2md-tauri`) собрал
байт-в-байт тот же `build_request()` (модель `gemini-3.6-flash`, тот же промпт/схема/
`generation_config`), что и `ocr.rs:937`, и отправил его на реальный
`https://generativelanguage.googleapis.com/v1beta/interactions` с реальным `GEMINI_API_KEY` из
`.env` doc2md-tauri, на тестовом скане `.planning/ocr-bench/letter-stamp/ORIGINAL.jpg`. Сырой
ответ сохранён — `.planning/D0-regression2-live-response.json`.

Реальный ответ содержит **только** плоский `usage` (ключа `usageMetadata` нет вовсе):
```json
"usage": {"total_tokens":4223,"total_input_tokens":1263,"total_output_tokens":789,
          "total_thought_tokens":2171, ...}
```
Порт `parse_gemini_usage` **до** фикса (только `usageMetadata`) на этом реальном ответе:
`total_tokens = 0` — регресс воспроизведён буквально, не по аналогии. Порт **после** фикса
(`usage` сначала): `total_tokens = 4223`.

**Вердикт: ДА, доказано живым вызовом.** Smoke-ассерт «одна живая конвертация → токенов
посчитано > 0» краснеет на pre-fix коде и зеленеет на post-fix — воспроизводимо, не текстом.

## Регресс 3 — Route_API_1C: «почему визиком не участвует, в пятницу же работало» (27.07)

**Симптом.** Visicom перестал побеждать в каскаде геокодера, выигрывала интерполяция Geoapify.

**Коммиты.** `ce71a9f` (24.07, `strict.py`: Visicom получает сырой текст 1С вместо развёрнутого
Gemini-имени улицы) и `3bd2250` (27.07, ступень «саме прізвище», прод-инцидент Пустомиты).

**Причина (из тела `ce71a9f`).** Собственная адресная база Visicom индексирует короткую бытовую
форму улицы, а Gemini разворачивает её до официальной («Грушевського» → «Михайла Грушевського»)
ради Geoapify/OSM. Полное имя ломало текстовый поиск Visicom — живой API возвращал посторонний
POI. Дословно: «Живий прод-тест (після ввімкнення `VISICOM_API_KEY`) показав».

**Живой пруф.** Скрипт `.planning/d0-proof-scripts/d0_regression3_live.py`
(`./.venv/Scripts/python.exe .planning/d0-proof-scripts/d0_regression3_live.py` из корня
`Route_API_1C`, нужен `.env` с `VISICOM_API_KEY`) импортирует реальную
`app.services.geocoder.visicom.search_visicom_candidates` (не копию — саму функцию из репо) и
вызывает её дважды с реальным `VISICOM_API_KEY`, на адресе прод-инцидента (Пустомити, вул.
Грушевського, 7):
- **pre-fix** (`city="Пустомити", street="Михайла Грушевського", house_number="7"` — структурный
  запрос с полным офиц. именем, как до `ce71a9f`): `candidates: []` — **дом не найден вообще**.
- **post-fix** (`raw_text="Пустомити, вул. Грушевського, 7"` — сирий текст 1С, как после
  `ce71a9f`): 5 кандидатов `adr_address`, среди них `name="7", street="Грушевського"` —
  **дом найден**.

Сырой результат — `.planning/D0-regression3-live-response.json`.

**Вердикт: ДА, доказано живым вызовом (не только историей).** Дефект и фикс воспроизведены
прямым вызовом реального Visicom API на реальном инцидентном адресе — не текст из commit
message, а observable-разница `[] → adr_address`. У проекта уже есть регресс-набор `gold_50` и
бенч (`e2d6f6f`), плюс флаг `--api` для прогона против живого сервиса (`fd612fd`): материал для
smoke-команды существует, не хватало только обязательности её вызова в гейте.

## Следствие для спеки 010

`N=2` ≥ порога → smoke-контракт входит в 010 отдельными слайсами, `tasks.md` расширяется,
спека переутверждается пользователем.

Две поправки к форме, которые дала разведка (обе — сужение, не расширение):

1. **Smoke объявляется проектом, а не системой.** Регрессы 2 и 3 ловятся совершенно разными
   командами (одна конвертация PDF против Gemini / прогон `--api` по gold-набору). Общего
   исполнителя быть не может — контракт системы это поле `smoke` в `harness.json` и правило
   «красный smoke = слайс не закрыт».
2. **Smoke требует живых ключей и потому не может быть частью обычного оракула.** Он платный,
   медленный и сетевой. Место вызова — гейт слайса рядом с оракулом, с явным пропуском и
   громкой записью в run-log, если ключей нет (иначе повторим историю с `--skip-attest`:
   тихий пропуск станет нормой).
