01 Проблема

Ми ставимо скіли так, як ніколи
не ставили б npm-пакет

Довіра за замовчуванням

Скіл кладеться в ~/.claude/skills — і виконується з тими ж правами, що й агент: файли, мережа, процеси, змінні оточення.

Ревʼю немає

Між «побачив у треді» і «встановив» немає жодного кроку. Ні підпису, ні CVE-фіду, ні code review.

Два вектори, не один

Текст скіла атакує модель (prompt injection). Код скіла атакує машину (ексфільтрація, RCE). Це різні атаки в одному файлі.

Питання, на яке треба відповісти до встановлення, одне: чи безпечно це ставити?

Сказати: ключова асиметрія — npm-пакет ми хоч якось перевіряємо, а скіл ставимо за скріншотом із твітера. При цьому прав у скіла більше.
02 Інструмент

SkillSpector — сканер скілів до встановлення

Що це

CLI від NVIDIA. Сканує директорію, git-репо, URL або zip зі скілом і дає вердикт. Apache-2.0, Python, 14 467 ★, останній реліз v2.8.2 — 7 серпня 2026.

Що всередині

68 патернів у 17 категоріях: prompt injection, ексфільтрація даних, privilege escalation, supply chain, memory poisoning, tool misuse, AST-аналіз небезпечних викликів, taint-трекінг, YARA-сигнатури, MCP least privilege і tool poisoning.

Частина конвеєра

Той самий сканер живить NVIDIA Verified Skills — каталог скілів, які пройшли перевірку й підписані.

Стадія 1 · статика

Regex + Python AST + YARA + запит до OSV.dev за реальними CVE залежностей. Швидко, офлайн, без ключів. Високий recall, помірна precision.

Стадія 2 · LLM (опційно)

Оцінює намір і контекст, відсіює хибні спрацювання, пише пояснення людською мовою. Precision ≈ 87%. У промпті є анти-джейлбрейк-захист.

Сказати: дві стадії — це і є вся архітектура. Статика ловить багато й з шумом; LLM пояснює й чистить. Статики достатньо для гейта, LLM — для розбору.

Без Python взагалі

Пінити версію обовʼязково

Ставити тег (@v2.8.2), не HEAD. Чому — покажу на слайді 10: імена категорій між версіями їдуть.

Windows-нюанс

uv кладе shim у ~/.local/bin. Якщо його немає в PATH — не воювати з PATH, а вказати шлях явно.

Сказати: це буквально одна команда. Барʼєр входу нульовий — тому немає причини не поставити її перед наступним встановленням скіла.

05 Як цим керувати

Exit code і JSON — стабільний контракт

ExitЩо означає
0Скан пройшов, ризик ≤ 50 (SAFE або CAUTION)
1Скан пройшов, ризик > 50 → DO_NOT_INSTALL
2Помилка: поганий вхід, нечитабельне джерело
RecommendationДія гейта
SAFEпускати
CAUTIONпопередити людину
DO_NOT_INSTALLблокувати

--format json дає повний звіт, --format sarif — SARIF 2.1.0 для CI та IDE. --baseline глушить уже розібрані знахідки, щоб повторний скан показував тільки нове.

Важливо: exit code склеює SAFE і CAUTION в один 0. Якщо треба розрізняти — читати поле recommendation з JSON, а не код виходу.

Сказати: саме через цей контракт сканер вбудовується в чужий pipeline за півгодини — не треба парсити текст, є код виходу і JSON.
06 Налаштування

LLM-стадія без жодного API-ключа

SKILLSPECTOR_PROVIDERКреденшлиМодель за замовчуванням
claude_cliнемає — логін локального CLIрантайм claude
codex_cliнемає — логін локального CLIрантайм codex

nv_buildNVIDIA_INFERENCE_KEYdeepseek-v4-flash
bedrockAWS SigV4claude-sonnet-4-6

Чому це важливо

У вас уже є оплачений claude або codex. SKILLSPECTOR_PROVIDER=claude_cli — і друга стадія працює через наявний логін, без нового ключа й без нового рахунку.

Субпроцес ізольований

CLI запускається в hardened-режимі: інструменти вимкнені, MCP вимкнений, read-only sandbox, недовірений вміст скіла подається тільки через stdin.

Коли LLM не треба

--no-llm = статика. Швидко, офлайн, і вміст файлів не покидає машину. Для масового гейта беріть саме це.

Сказати: це найнедооціненіша опція. Всі бачать «потрібен ключ» і зупиняються — а насправді є режим на вже наявному логіні.

08 Демо 3 · інтеграція в свій гейт

Сирий вердикт — не завжди ваш вердикт

Статика високорекольна: скіл, який описує небезпечний патерн (наприклад, вчить захищатися від prompt injection), отримує HIGH так само, як справжня малварь. Тому в нас над сканером тонка обгортка, яка розділяє код і прозу.

node tools/skill-scan.js ./badskillнаш гейт · exit 3
BLOCKED  raw=CRITICAL(100)  blocking=7 advisory=3  exec=1/2  badskill
  ✗ [CRITICAL/hard-block]     AST8 Dangerous Code Execution   sync.py:5
  ✗ [HIGH/executable-code]    AST1 Dangerous Code Execution   sync.py:5
  ✗ [CRITICAL/hard-block]     TT5  Data Flow                  sync.py:5
  ✗ [HIGH/executable-code]    E2   Data Exfiltration          sync.py:2
  ✗ [HIGH/executable-code]    SC2  Supply Chain               sync.py:6
  ✗ [HIGH/hard-block]         YR4  YARA Match                 SKILL.md:5
  ~ [HIGH]                    P1   Prompt Injection           SKILL.md:5
  ~ [HIGH]                    P6   System Prompt Leakage      SKILL.md:5
  ~ [HIGH]                    TM1  Tool Misuse                sync.py:6

blocked exit 3

HIGH у виконуваному файлі, або жорстка сигнатура (YARA-малварь, taint-ланцюг credential→мережа) — байдуже в якому файлі.

review exit 4

HIGH тільки в markdown — порада людині, не блок. Скіл про безпеку має право згадувати небезпечні речі.

pass exit 0

Лише LOW/MEDIUM. Плюс doctor тепер друкує [PASS] SkillSpector 2.8.2 (global) — щоб «гейт увімкнений» було станом, а не вірою.

Сказати: головна думка слайда — сканер дає сигнал, політику пишете ви. NVIDIA це прямо каже: наскільки суворий гейт — рішення того, хто інтегрує.

  → YAML-ключ у довідковому документі про дизайн.

Чому це не провал інструмента

Статична стадія свідомо високорекольна: краще показати зайве, ніж пропустити. Precision витягує друга стадія — та сама LLM, яку видно на слайді 07.

Що з цим робити

skillspector baseline ./skill -o .skillspector-baseline.yaml — прийняти розібрані знахідки один раз. Далі скан показує тільки нове.

Головний висновок

Сканер не заміняє людину — він звужує те, що людина дивиться, з 86 скілів до 5. Пʼять розборів по хвилині проти повного code review — це і є виграш.

Сказати: не продавати інструмент як чарівну кулю. Чесна рамка: 86 скілів → 5 до розбору → 0 реальних загроз. Наступного разу серед пʼятірки може бути справжня.
11 Пастка

Оновлення сканера може тихо послабити ваш гейт

У нас уже стояв SkillSpector v2.1.3. Оновлення до v2.8.2 нічого не зламало — і саме тому це небезпечно.

той самий звіт, дві версії правилвиміряно
Імена категорій:
  v2.1.3   Behavioral AST   Taint Tracking
  v2.8.2   Dangerous Code Execution   Data Flow
           ↑ ті самі правила AST1..AST9 і TT1..TT5, інша назва

Наш гейт зі старими іменами:
  ДО фікса    verdict=blocked  blocking=6  advisory=4
  ПІСЛЯ фікса verdict=blocked  blocking=7  advisory=3
  → AST1 «exec() call detected» зʼїхав з blocked у review

Скіл, у якого є ТІЛЬКИ AST1:
  зі старими іменами  review   (exit 4 — просто попередження)
  з новими іменами    blocked  (exit 3 — не ставимо)

Помилок немає, тести зелені, вивід той самий. Гейт просто перестає блокувати частину знахідок. Тому в репо тепер лежить тест, який ганяє живий бінар на відомо шкідливій фікстурі й падає, щойно чергове перейменування зробить категорію нерозпізнаною.

Сказати: мораль ширша за SkillSpector: якщо ваш гейт хардкодить рядки з чужого інструмента — потрібен тест проти живого інструмента, інакше апдейт мовчки змінює політику.

13 Межі й підсумок

Чого SkillSpector не робить

Це не пісочниця

Він позначає ризик до встановлення. Якщо ви поставили скіл попри попередження — він його не стримає.

Він не запускає код

Аналіз статичний: regex, AST, YARA плюс опційна LLM-оцінка вмісту. Рантайм-поведінку не бачить.

LLM-стадія відправляє файли

Увімкнена за замовчуванням — вміст файлів іде до провайдера. --no-llm лишає все локально. SC4 у будь-якому разі шле імена залежностей на OSV.dev.

Сліпі зони

Не-англійський текст, атаки в зображеннях, компільований чи зашифрований код, і без мережі до api.osv.dev перевірка CVE падає на короткий вбудований список.

Що зробити після цієї доповіді, у порядку вартості:

  • Одна команда — uv tool install --python 3.12 'git+https://github.com/NVIDIA/skillspector.git@v2.8.2'
  • Одна звичка — skillspector scan <скіл> --no-llm перед кожним встановленням чужого скіла
  • Один тест — якщо загортаєте сканер у власний гейт, пиньте версію і тримайте тест проти живого бінаря
Сказати: закінчити на тому, що це defense-in-depth, а не срібна куля. Але це найдешевший шар з усіх — і єдиний, який працює до інсталу.
