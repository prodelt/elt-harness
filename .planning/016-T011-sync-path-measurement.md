## Где остались эти секунды — и почему это не судья

Синхронная часть теперь целиком состоит из оракула. Профиль прогона при полностью прогретом кеше
(тесты не гоняются, `82/82 passed in 0.0s`, общее время 14 с):

- `git status` / `git diff` — 0,1 c;
- `require` модулей выборки — 0,01 c;
- **`computeEntry` по 66 тест-файлам — 11 c** (расчёт хеша замыкания для кеша оракула);
- остальное — запуск процесса и печать отчёта.

Проверенная и **отклонённая** гипотеза: замыкания тестов сильно пересекаются, значит один и тот
же файл читается десятки раз, и памятка чтения на прогон должна срезать основное время. Замер:
11,10 c без памятки → 13,56 c с памяткой, то есть выигрыша нет (стоимость сидит не в
`readFile`, а в резолве require-графа). Правка откачена, в коде её нет.

Вывод: дальнейшее ускорение синхронной части — это оптимизация **резолва замыкания в кеше
оракула**, а не работа с судьёй. Судья из критического пути вынесен; отдельным кандидатом в
следующую спеку остаётся `computeEntry` (11 c при 66 файлах).
