# ELT-CODE (B) — eval-флайвил: дизайн

> Статус: согласовано в grill-сессии 2026-06-20. Продолжение `ELT-CODE-DESIGN.md` (режим A доказан).
> **Перило №1 (анти-AMOS, не обсуждается):** B = **on-demand + advisory**. Ничего не инжектится,
> ничего не правится само, нет фонового контура. B запускается рукой, человек на файле — гейт.
> Метод: B — НЕ новая система, а **расширение существующего** `tools/update-judge-verdicts-index.js`.

## Рамка: B — это линза, не маховик

«Флайвил» = маховик = петля. Перило №1 запрещает петли. Поэтому B по форме —
**линза**: on-demand отчёт по корпусу вердиктов, который читает человек и сам решает.

Три формы выхода (решено в grill, Q0):
- **(a) Линза** — отчёт-диагностика по корпусу. Человек читает, сам думает. **← строим сейчас.**
- **(b) Советник** — генерит advisory-предложения, человек применяет руками. **← потолок, дорастаем.**
- **(c) Маховик** — правит сам. **← вычеркнут навсегда** (см. «Ворота к (c)»).

Почему не сразу (b)/(c): корпус = **1 реальный вердикт**. Любое «самоулучшение» на n≈1 —
галлюцинация сигнала, ровно тот self-deception, от которого AMOS сдох 2026-06-18. Линза честна
при любом n (просто показывает что есть); советник требует зрелости; маховик требует MLOps-контур.

**Ключевой принцип:** B улучшает **ровно одну вещь — калибровку судьи.** Это единственный компонент,
чьё качество измеримо из корпуса вердиктов. Всё «самоулучшение шире судьи» = галлюцинация скоупа.

## v1 — линза (a), строим

Расширяем `tools/update-judge-verdicts-index.js` (НЕ новый тул: парсер один, данные одни, читатель
один — второй тул = дублирование парсера + рассинхрон схемы). Дефолтный вывод становится богаче.

| Слой | Что меряет | Из чего | Зуб |
|---|---|---|---|
| **(i) Здоровье судьи** | дисперсия S-оценок (stdev), перекос по осям, флаг вырождения | S1-S4 в вердиктах | детектор «судья — резиновый штамп» |
| **(ii) Качество работы** per-project | тренд S во времени (↑/↓/→), какая ось проседает | хронология вердиктов | подсвечивает где подтянуться |
| **recall-крючок** | счётчик `judge_miss` (если есть) | человеко-кормимые события | внешняя валидность судьи |
| **model×complexity** | block%/S в разрезе | те же поля | бесплатный фильтр |

### Два зуба (валидация на границе доверия — здесь ponytail запрещает лениться)

- **Зуб №1 — метка доверия.** (ii) на малом `n` врёт: «S4=3.2, n=2» — шум, не тренд, но выглядит
  как факт. Линза **всегда** показывает рядом с цифрой `n` + разброс. Не голую цифру. Этим порог
  зрелости встроен в линзу, а не вынесен в отдельную фазу.
- **Зуб №2 — судья как прибор.** S1-S4 — оценки **судьи**. Если прибор врёт (вырождение из (i)),
  то (ii) врёт вместе с ним. Линза читает здоровье судьи **первым**; если судья выродился — раздел
  (ii) помечается «недостоверно, судья под вопросом». Баннер вверху гейтит доверие к (ii).

### Шов: схема `judge_miss` (зафиксирована сейчас, наполняется потом)

recall = единственный мост к **внешней** валидности судьи (поймал ли он реальные проблемы; (i) без
него меряет только внутреннюю консистентность — судья может быть стабильно-НЕправ). Сбор —
**только человеко-кормимый**, не авто-харвест (авто-связывание «баг→вердикт» = эвристика, которая
врёт + фоновый контур = AMOS). Поймал промах судьи → одна строка в тот же `session-ledger.jsonl`:

```json
{"type":"judge_miss","ts":"…","ref_verdict_ts":"…","what":"судья дал PASS, всплыл баг X"}
```

Линза считает recall = поймано/(поймано+промахи), когда события есть; раздел скрыт при пустоте
(честное молчание). Тулинг вокруг крючка в v1 **не строим** — это крючок, который ждёт, не фича,
которая гниёт. Риск дисциплины приемлем: при пустоте ничего не ломается.

### План сборки (ценность вперёд, каждая фаза — proof)

Корпус сейчас: 1 реальный (Fasoli) + 5 demo live-fire (`~/.claude/tmp/elt-judge-livefire/`) как
**фикстуры для тестов**. Proof фаз B опирается на фикстуры; реальный сигнал — по мере накопления A.

- **B0 — Здоровье судьи (i) + метка доверия.** stdev/перекос/флаг вырождения + колонка `n`+разброс.
  *Proof:* `--self-check` на фикстурах показывает дисперсию и флаг вырождения; прогон на каноне.
- **B1 — Тренд per-project (ii) + гейт доверия (зуб №2).** ↑/↓/→ по хронологии + баннер «судья здоров?».
  *Proof:* тренд на проекте с ≥2 вердиктами; баннер гейтит (ii) при подставленном вырождении.
- **B2 — recall-крючок.** Парсинг `judge_miss` + счётчик recall.
  *Proof:* фикстура `judge_miss` → recall считается; без неё раздел скрыт.

**Критерий «B v1 (линза) готов»:** все 3 фазы с proof + один реальный прогон линзы по канон-корпусу
читается человеком и даёт осмысленный отчёт (даже если сигнал помечен слабым из-за малого n).

## Отложено — советник (b), НЕ в v1

Дорастаем, когда корпус созреет. Форма:

- **Скоуп правок — только судья:** рубрика (`constitution.md`) + конфиг модели судьи (Sonnet↔Opus).
  НЕ скилы, НЕ диспетчер, НЕ архитектура (их метриками вердиктов не оценить → правит человек по-крупному).
- **Механика:** линза добавляет раздел «Предложения» (advisory-текст) → человек правит файл руками →
  коммитит. **Гейт = git commit человеком.** Нет авто-применения, нет PR-бота, нет отдельного канала.
- **Порог зрелости — на советника, не на линзу.** Линза честна всегда (с меткой доверия); советник
  **молчит, пока сигнал помечен слабым**. Число порога НЕ хардкодим (ложная точность на n=1) —
  привязываем к разбросу (говорит про ось, только когда перекос отделим от шума) и калибруем на корпусе.
- **Топливо (b):** накопленные `judge_miss` → «судья систематически пропускает X → ужесточи ось Y».

## Ворота к (c) — автопетля: условия, не дата

(c) вычеркнут из v1, но не из суеверия. (c) перестаёт быть AMOS-рецидивом и становится легитимным
online-learning **только когда пройдены ВСЕ четыре ворот** (И, не ИЛИ):

1. **(b) доказал точность вживую** — советник был прав M/N раз с высоким M. Автопетля = (b), которому
   перестал смотреть на руки; перестать можно только насмотревшись. Доверие — из данных, не из идеи.
2. **Held-out валидация** — правка проверяется на отложенных вердиктах, что её не порождали. Иначе
   Goodhart неизбежен (оптимизирует то, на чём учится; «улучшает» block% ослаблением рубрики). Нужны
   **сотни** вердиктов.
3. **Auto-rollback по внешнему сигналу** — recall на held-out упал → откат. Стоит на потоке `judge_miss`;
   пока промахи штучные — откатывать не на чём.
4. **Версионирование + аудит рубрики** — каждая авто-правка = версия с diff и причиной, откатываемая.

**Почему ворота, вероятно, не наступят — и это правильный потолок:** даже при всех четырёх выигрыш мал
(экономит «человек раз в N прогонов жмёт да» — минуты в месяц), стоимость огромна (MLOps-контур). ROI
отрицательный, пока частота правок не станет узким местом — на горстке проектов не наступит.
**(a)→(b) = ~95% ценности при ~5% риска; (c) = последние 5% ценности за 95% риска и весь R&D.**

**Если (c) когда и придёт — с безопасного края, не с рубрики:** авто-выбор **модели** (Sonnet↔Opus,
обратимо мгновенно, не трогает критерий) — низкий риск; авто-правка **рубрики** (Goodhart + глобальный
blast radius) — высший, автоматизируется последним.

**Урок AMOS:** умер не от петель — от петель, включённых **без этих ворот**, на доверии к идее вместо
данных. «Когда внедрим» = **«когда данные заставят»**. Путь к (c) идёт строго через (a)→(b); перепрыгнуть
нельзя — без пройденного (b) любая (c) = AMOS с новым именем.
