# ELT-CODE v0.6 — апгрейд на нативные движки

> Статус: дизайн, 2026-06-24. Продолжение `ELT-CODE-DESIGN.md` (A, собран) + `ELT-CODE-B-DESIGN.md` (линза, отложена).
> **Перило (анти-AMOS, не обсуждается):** всё on-demand, человек вызывает рукой, петля
> самозавершается по внешнему сигналу (судья), нет фонового контура / per-turn инъекции.
> **Метод:** не новая система — перестановка проверенного метода v0.5 на нативные рельсы Claude Code 2.1.187.

## Тезис

Сам метод elt-code (судья-гейт, спека-как-контракт, дробление контекста) — впереди многих.
Отстаём в **механике исполнения**: гоняем руками то, что платформа теперь делает нативно
(петля, structured output, параллель, токен-учёт). Это «переставить метод на рельсы», не «догонять идею».

Версия Claude Code = 2.1.187 (верх changelog). По номеру не отстаём вообще — отстаём в эксплуатации
уже-доступного (~40-50% возможностей).

## Ключевая разблокировка: судья = оракул завершения петли

У elt-code **уже есть** сигнал pass/block — судья (Шаг 4). Любой петле нужно ровно одно: знать,
когда остановиться. Соединение нативного `/loop` (dynamic) с судьёй делает COMPLEX-петлю
самоуправляемой и **анти-AMOS-чистой**:

- Останов решает **судья** (отдельный субагент по рубрике), а не самооценка модели → нет
  self-deception, от которого умер AMOS.
- Человек **вызвал** `/loop` рукой → нет фонового контура.
- Каждое пробуждение (`ScheduleWakeup`) = **свежий контекст** → token-floor лечится механически
  (Шаг 3.5 «дроби руками» становится автоматическим).

Это НЕ ralph-loop (где выход зависит от того, не соврёт ли модель «DONE»). Здесь выход — внешний
вердикт по рубрике.

## Три механизма «петли» — не путать

| Механизм | Что | Кто решает «продолжать» | Роль в v0.6 |
|---|---|---|---|
| Нативный `/loop` (dynamic) | само-темп через `ScheduleWakeup`, свежий контекст | Claude по сигналу судьи | **двигатель** контура слайсов |
| Судья (Шаг 4) | вердикт pass/block по рубрике | отдельный субагент | **клапан** контура |
| `loop-guardian.js` (хук, сейчас НЕ подключён) | детект застревания (6× одно действие → BLOCK) | предохранитель | **аварийный тормоз** (только в loop-сессии) |
| ralph-loop (плагин) | stop-хук кормит тот же промпт, бесконечно по умолчанию | модель (completion-promise) | **НЕ берём** — выход на доверии к модели |

## План апгрейда по тирам

**Тир 1 — даром, без кода:**
1. `/usage` вместо ручного JSONL-разбора (юзер-команда).
2. `defaultMode: "bypassPermissions"` → `"auto"` — classifier = зубы без спама, страхует авто-commit Шага 5.
   Применяется в новых сессиях. Значение `"auto"` подтверждено из `sdk-tools.d.ts`
   (`PermissionMode = acceptEdits|auto|bypassPermissions|default|dontAsk|plan`).

**Тир 2 — правка скила/доков:**
3. Судья (Шаг 4) → structured output со schema (рубрика уже = JSON-схема).
4. Сжать `MEMORY.md` — история AMOS в `archive/`.

**Тир 3 — новый контур (обкатать под присмотром):**
5. COMPLEX-путь → нативный `/loop` dynamic с судьёй-оракулом (Шаг 3.5 → 6). Сначала одна реальная
   COMPLEX-задача под присмотром, потом доверять. Обязательно: `loop-guardian` (в loop-сессии) + `max-iterations`.
6. #5 аудит → agent team (судья ∥ ponytail ∥ perf).

**Не трогать:** B-линза (качество = bespoke), тонкий PreCompact-слой, codegraph-first.
