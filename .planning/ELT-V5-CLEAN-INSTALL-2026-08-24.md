# Чистая установка и паритет клиентов (020/T012)

Дата прогона: 2026-08-25. Машина: Windows 10 Pro, node 24.14.0, git 2.51.0.
Профиль установки — ОТДЕЛЬНЫЙ (`CLAUDE_CONFIG_DIR` в scratch), а не рабочий: иначе «чистая
установка» проверялась бы поверх машины, где ELT уже стоит, и ничего бы не доказывала.

## Команды воспроизведения

```powershell
# 1. чистый профиль и чистый проект
$env:CLAUDE_CONFIG_DIR = "<пустой каталог>"
claude plugin marketplace add "C:\Claude playground\ELT-v5-one-hour"   # или prodelt/elt-harness
claude plugin install elt@elt
claude plugin list
claude plugin details elt@elt

# 2. диагностика ИЗ УСТАНОВЛЕННОЙ копии, стоя в пустом проекте
$cache = (Get-Content "$env:CLAUDE_CONFIG_DIR\plugins\installed_plugins.json" | ConvertFrom-Json).plugins.'elt@elt'[0].installPath
node "$cache\bin\doctor.js"
node "$cache\bin\session-start.js"    # в чистом проекте обязан молчать

# 3. паритет трёх клиентов
node tools/host-surface.js
node tools/host-surface.js --sync-clients --dry-run
node tools/host-surface.js --sync-clients

# 4. манифесты
claude plugin validate . --strict
```

## Что осталось открытым

1. **Дубль хуков на машине, где ELT жил до плагина.** `~/.claude/settings.json` вызывает
   `elt-session-brief.js` и `dirty-exit-gate.js` — те же две функции, что теперь даёт плагин.
   На такой машине сводка печатается дважды. Плагин их не трогает: это пользовательский
   профиль, и удалять оттуда файлы, чей источник ему неизвестен, он не имеет права (тот же
   запрет, из-за которого судья заблокировал `4603a9e`). Снять дубль пользователь может сам,
   убрав две записи из `hooks` в `settings.json`; порядок описан в `docs/INSTALL.md` §6.
   На чистом профиле, где мерялась установка, дубля нет по построению.

2. **Вес установленной копии — 16 МБ.** Разбивка: `archive/` 3,3 МБ, `presentation/` 2,6 МБ,
   `tools/` 2,6 МБ, `specs/` 1,7 МБ; сама поверхность плагина занимает 204 КБ
   (`bin/` 120 КБ + `agents/` 52 КБ + `skills/` 32 КБ). То есть 98% установки — история и
   материалы разработки, которые пользователю плагина не нужны. Это не отказ (установка
   проходит, доктор зелёный) и не входит в T012: сужение поставки — отдельная работа, здесь
   она только измерена.

3. **Пять из шести глобальных хуков по-прежнему без источника в репозитории.** T012 вернул в
   репозиторий два (`session-start`, `session-stop`). Остальные — `precompact-handoff.js`,
   `resume-handoff.js`, `stuck-detector.js`, `context-autocompact-guard.js` — остаются
   глобальными-только, как записано в аудите 020/T004. Ни один из них плагин не трогает.

## Дефект гейта, найденный при закрытии этой задачи

Слайс T012 меняет 12 файлов, шесть из которых вне объявленной `[files:]` зоны. Гейт должен был
разбудить судью триггером `out-of-scope`. Вместо этого он выдал `l0-clean: риск-триггеров нет,
судья не звался`.

Причина найдена и записана в `.elt/ledger.jsonl` как `harness-defect` /
`task-text-truncated-to-first-line`:

`parseTasksFile` (`tools/elt.js:74–83`) кладёт в текст задачи ТОЛЬКО строку с маркером
`- [ ] **T012** …`. Продолжение многострочной задачи — вместе со строкой `[files: …]` — теряется.
Доказательство прямое, из `judge-desc.json` живого прогона:

```
tid: T012
taskText: "T012 Чиста установка і client parity: додати versioned plugin hooks для"
```

Одна строка. `taskScopeFiles(taskText)` не находит в ней `[files:]`, поэтому scope-триггер
молчит — и молчит он не только здесь: все задачи планов 019 и 020 многострочные.

Прямой прогон `evaluate()` с ПОЛНЫМ текстом задачи даёт `judgeNeeded: true` и триггер
`out-of-scope` со списком всех 12 файлов. Второй дефект того же разбора виден там же:
`taskScopeFiles` режет список по запятым, а в `tasks.md` файлы разделены пробелами — так что
даже при полном тексте зона схлопнулась бы в один несуществующий глоб.

**Что сделано в этом слайсе:** дефект записан в журнал и судья позван вручную — с полным
текстом задачи, через `tools/judge-invoke.js`. Вердикт `pass`, семь оснований, включая разбор
файлов вне `[files:]` (судья счёл их вынужденным следствием: код хуков, на которые ссылается
`hooks/hooks.json`, и механизм паритета, требуемый формулировкой задачи). Штатный proof слайса
остался `l0-clean` — подменять его вручную нельзя, люк самозаверения снят спекой 011 T011, и
запись обязана отражать то, что гейт сделал НА САМОМ ДЕЛЕ.

**Что не сделано:** сама починка. Правка `parseTasksFile` — вне `[files:]` T012 и вне её темы;
выносится отдельным слайсом. До него scope-триггер L0 остаётся мёртвым, и это надо учитывать
при чтении вердиктов `l0-clean` в планах 019/020.
