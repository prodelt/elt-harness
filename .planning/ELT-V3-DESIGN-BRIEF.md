## 2. Три схемы (детали и mermaid — в артефакте)

- **A — маршрутизация по риску** (основа): L0 механика по codegraph (0 LLM, <5 c) → L1 оракул по
  impact-выборке → L2 smoke реального продукта → L3 ОДИН судья только по риск-триггеру,
  вердикт `pass / block / inconclusive`. `inconclusive` = коммит с меткой + очередь ревью,
  второго раунда на том же слайсе нет (осцилляция физически исключена).
- **B — проверка после коммита с авто-revert**: дешёвый слой пропускает коммит, тяжёлое асинхронно,
  красное откатывается механически; merge в main только для веток с меткой verified.
- **C — граф как несущая конструкция + слой эволюции**: scope/impact/риск из codegraph МЕХАНИЧЕСКИ
  (adoption codegraph сейчас 4/993 — граф должен работать независимо от того, звал ли его агент);
  сверху — разбор трейсов → правка харнесса с ПРЕДСКАЗАНИЕМ эффекта → фальсификация следующей
  итерацией → регресс-гейт правки на judge-bench.

**Порядок: A → C слоем над ней → B режимом.** Со слоя эволюции начинать нельзя — на 77% ложных
блоков он выучит шум. Флот: сначала A, потом живой A/B (при гейте 50% потолок Амдала ≈ 2,0× —
иначе A/B меряет стоимость гейта, а не эффект флота).

## 3. Требования пользователя, добавленные 31.07 (В АНАЛИЗЕ НЕ РАСКРЫТЫ — обязательны в спеке)

### 3.1 Dogfood: спека 011 реализуется САМИМ новым подходом
Каждый слайс 011 закрывается уже построенной частью v3 — новый контур проверяется боем по ходу
стройки, а не после. Практически: как только L0 написан — он включается в гейт следующего слайса;
как только impact-оракул готов — им гоняется следующий слайс. Отказ нового слоя на живом слайсе =
пруф дефекта, а не повод откатиться к старому пути.

### 3.2 Качество тестов не измеряется — это отдельная слепая зона
Оракул зелёный ровно настолько, насколько честны его тесты (W3 из карты слабых мест). Сейчас
качество per-project оракула не проверяется ничем: `project-bootstrap verify` смотрит только на
непустоту строки оракула. Судья ловит бутафорские тесты промптом — ненадёжно и дорого.
В спеку нужен механический слой: мутационное тестирование или эквивалент, покрытие изменённых
строк, «новый код без нового runnable-чека = block», расширение red-proof (тест обязан падать на
baseHead) с текущего частичного применения на все слайсы. Метрика: тест, который не падает при
поломке проверяемой им логики, обязан ловиться механически, а не судьёй.

### 3.3 Context7 обязателен перед кодом с внешней библиотекой
Галлюцинации API и устаревшая документация не должны быть возможны в нашей системе. Сейчас `ctx7`
(PowerShell, on-demand) — дисциплина без зубов. В спеку: контур, при котором работа с внешней либой
без свежей документации механически не проходит (минимум — L0-правило на новую зависимость/новый
внешний импорт, требующее пруфа обращения к context7).
