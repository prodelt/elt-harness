## 3. Диагноз — 5 корневых причин хаоса

1. **Инварианты живут в прозе → исполнение вероятностное.** Всё, что было хуком, исполнялось
   всегда (даже слишком: false positives). Всё, что было строкой SKILL.md («коммить на зелёном»,
   «веди run-log», «зови судью-субагента»), исполнялось только когда модель случайно следовала.
   Run-log предписан elt-loop v0.2 — файла не существует даже в лучшем проекте.
2. **Шов elt-code / elt-loop.** Инварианты (оракул → коммит → STATE) есть только на loop-пути.
   75% работы идёт через elt-code-маршруты (diagnose, инлайн-фиксы, преза) — там НОЛЬ инвариантов:
   ни веток, ни коммитов, ни оракула. Отсюда «хаотично в разных проектах».
3. **Per-project установка копированием → дрейф и дыры.** Зубы стоят в 4 репо (копии разных
   версий), в 2 активных проектах нет даже git. judge-closeout-gate «спит до первого /pipeline»,
   а /pipeline = 1/38 → **гейт охраняет пустоту** (тот же вывод, что аудит 2026-06-26 — паттерн
   повторяется, значит чинится не прозой).
4. **Состояние = проза.** STATE.md опять разросся в журнал с многоабзацными инцидентами; машиной
   не проверяем → деградирует молча. tasks.md (чекбоксы) — единственный формат, который держится,
   потому что он механически проверяем.
5. **Автономность ручная.** Драйвера нет: юзер сам пинает `/elt-loop продолжай`, петля 30 раз
   останавливается спросить, fresh-context правило в прозе игнорируется, ralph-wiggum установлен
   но выключен, ScheduleWakeup не использован ни разу.

Класс-топ из 92 ошибок: codegraph-read-gate блокирует Read → ретраи-налог; block-dangerous-git
false positives (блокировал безобидный `cd && echo`); чужой venv (hermes-agent) перехватывает
python → «No module named pytest»; PS5.1 кодировка.

## 4. Архитектура ELT v2 — «код-энфорсмент, тонкий скилл, внешний драйвер»

**Принцип:** всё, что должно случаться ВСЕГДА — в коде (hooks + CLI + driver-цикл).
Модель делает только то, что требует интеллекта: имплемент слайса. Auto-commit — это не
поведение модели, это детерминированный шаг драйвера после зелёного оракула.

```
                ┌────────────────────────────────────────────────┐
                │  /elt  (ОДИН скилл ~60 строк, merge code+loop) │
                │  интент → слайс → вызовы elt CLI               │
                └──────────────┬─────────────────────────────────┘
                               │
   ┌───────────────────────────▼───────────────────────────────┐
   │  tools/elt.js  (CLI, один файл, без deps)                 │
   │  status | oracle | slice next | commit | loop-log         │
   │  конфиг: .harness/harness.json (оракул, python, ветки)    │
   │  состояние: .harness/state.json (пишет ТОЛЬКО CLI)        │
   └───────┬──────────────────────────────┬────────────────────┘
           │                              │
 ┌─────────▼──────────┐        ┌──────────▼──────────────────────┐
 │ Хуки (глобальные)  │        │ tools/elt-loop.ps1 (ДРАЙВЕР)    │
 │ SessionStart: git  │        │ while [ ]-задачи && !kill:      │
 │  init/ветка        │        │   claude -p "<слайс>"  ← fresh  │
 │ Stop: dirty-exit   │        │   elt oracle (exit-код)         │
 │  gate              │        │   green → elt commit (авто)     │
 │ PreToolUse: git-   │        │   red   → retry 1 → стоп+отчёт  │
 │  guard (починен)   │        │ Task Scheduler = автопилот      │
 └────────────────────┘        └─────────────────────────────────┘
```

### 4.1 Один скилл `/elt` (замена elt-code + elt-loop; старые имена — алиасы-форварды)
- Есть открытые `[ ]` в `specs/*/tasks.md` → слайсовый режим автоматически.
- Задача без спеки → **микро-спека** (goal + oracle-команда, 1 слайс) — тем же путём, с теми же
  инвариантами. Исчезает шов: багфикс на 10 минут проходит через тот же oracle→commit, что и петля.
- diagnose / qa / design-studio остаются «линзами» внутри слайса, не отдельными дверями.

### 4.2 `elt` CLI — machine-readable ядро (чинит причины 1, 4)
- `.harness/harness.json` (per-project, создаёт bootstrap): `{"oracle": "PYTHONPATH=src python -m pytest tests/", "python": "D:/.../venv/Scripts/python.exe", "branch_policy": "feature", "autocommit": true}` — чинит и класс env-ошибок (чужой venv).
- `elt oracle` — прогнать объявленный оракул, exit-код = истина.
- `elt commit` — атомарный closeout: oracle green → `git add -A && git commit -m "<type>: <Txxx> <desc>"` → `[X]` в tasks.md → append `.harness/run-log.jsonl`. Одна команда — весь протокол, который сейчас размазан на 4 строки прозы и не исполняется.
- `elt slice next` — следующая `[ ]` задача как готовый промпт.
- `elt status` — git + oracle + план одним экраном (замена чтению STATE.md).
- STATE.md остаётся человеческими заметками, но перестаёт быть носителем протокола.

### 4.3 Git-зубы (чинит «нет авто-коммитов и ведения git»)
- **Хуки живут ТОЛЬКО в `~/.claude/hooks/`** (глобальный settings.json), per-project — только
  конфиг harness.json. Убирает дрейф копий (причина 3).
- **SessionStart:** проект без git → предложить `git init` + baseline-коммит громко (Itstep,
  lawyer_skill не повторятся). Кодовая задача на main → авто `git switch -c feature/<slug>`
  (политика из harness.json).
- **Stop-hook «dirty-exit gate»** (замена judge-closeout-gate): были Edit/Write + дерево грязное +
  оракул зелёный → block с «run `elt commit`». Судья из гейтов убран совсем — данные дважды
  (06-26 и сегодня) показали 0 исполнений; гейт, охраняющий пустоту, вреднее его отсутствия.
- block-dangerous-git: починить false positives; codegraph-read-gate: block → однократный warn.
- push остаётся ручным/по флагу (внешнее действие — риск).

### 4.4 Драйвер `elt loop` — «Клод промптит сам себя» (Anthropic-паттерн, чинит причину 5)
- `tools/elt-loop.ps1`: цикл `claude -p "<слайс-промпт>" --permission-mode acceptEdits` →
  `elt oracle` → green: `elt commit`, red: retry 1 → стоп с отчётом. Kill-switch-файл, caps
  `-Slices N -Minutes M`.
- Каждый слайс = свежий headless-процесс → fresh context ЖЕЛЕЗНО (context rot решён механикой,
  а не правилом «>2 слайса — /clear», которое игнорировалось).
- Это ralph-wiggum-паттерн + наши детерминированные oracle/commit-шаги, которых у ralph нет.
- Запуск: руками / из `/elt` / Windows Task Scheduler (ночной прогон) → настоящий автопилот.
- Судья v3 (опционально): драйвер после N коммитов гоняет `claude -p`-ревью на дифф → замечания
  в run-log. Advisory навсегда; гейт — только оракул.

### 4.5 Bootstrap v2 + fleet-doctor
- bootstrap: git init, harness.json (оракул спрашивается один раз), регистрация проекта в
  `~/.claude/harness-projects.json`.
- `doctor --fleet`: по реестру — репо? dirty>7 дней? оракул зелёный? Расширяет уже стоящий
  weekly Task Scheduler аудит.

### Что НЕ строим (ponytail)
Свой оркестратор/БД/дашборд; Agent SDK-приложение (`claude -p` достаточно); автопуш; переписывание
spec-kit (tasks.md формат оставляем — единственное, что доказанно держится); checkpoint-скилл
оставляем как есть (12/38 сессий — привычка прижилась).
