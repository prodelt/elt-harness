## Частина 1 — Вердикт по harness-системі

**Зрілість: висока. Головний розрив — не у фічах, а у ВИКОРИСТАННІ.**

### Що працює (сильні сторони)
- **Когерентна доктрина.** `Agent = Model + Harness` (guide+sensor+gate+steering) — це не гасло,
  а реально проведене через PLAYBOOK → skills → per-project зуби. Одна точка входу.
- **elt-loop спроєктований правильно.** Оракул = тести (не суддя), kill-switch, run-log,
  fresh-context правило, hard-cap 8, self-heal ≤3. Це рівно loop-engineering, без AMOS-театру.
- **Доведено живьём на AWE3.** US1+US2 закриті 10+ слайсами поспіль, husky-гейт спрацював
  (fmt-reject → fix → green). Це не теорія — петля пройшла end-to-end.
- **Анти-AMOS дисципліна засвоєна.** enforce-not-nag, per-project конфіг, no per-turn injection,
  «Done» тільки з proof. Пам'ять-як-указівник, не журнал.

### Слабкі місця (чесно)
1. **Оракул сильний рівно настільки, наскільки сильні тести.** elt-loop блискучий на проекті з
   чистим механічним оракулом. На проекті БЕЗ тестів (або з тестами, що б'ють у живу мережу —
   як `sudovi-master`) петля буксує на self-heal, бо «червоний» плаває. **Це найважливіший
   висновок для v2 бота: будувати test-first з офлайн-фікстурами.**
2. **Adoption gap (з твоїх же аудитів).** `/loop` 0/46, суддя 0/46, скіли ігнорилися 76% — до
   радикального спрощення elt-code→роутер (v1.0.0). Спрощення було правильним фіксом. Але петля
   й досі тримається на дисципліні юзера (глобальних авто-гейтів нема — свідомий вибір).
3. **Маятник «зуби ↔ спрощення».** Історія пам'яті показує цикл: додати суддю-гейт → human-override
   → зняти в репо; додати зуб ізоляції → зняти. Це здорова самокорекція, але сигналить, що система
   кілька разів перебудовувалась. Урок ponytail уже інтерналізований — тримати його.

### Рекомендація по системі (ponytail: НЕ додавати машинерію)
Система **завершена**. Не будуй нових скілів/хуків. Розрив — у застосуванні до реальних проектів.
Три конкретні кроки:
- **A. Другий live-fire.** v2 бот (`sudovi-fast`) — ідеальний доказ, що elt-loop генералізується
  поза AWE3. Реальний проект, який тобі потрібен, з можливим чистим оракулом.
- **B. Один checkable-передумова до elt-loop:** «чи має проект офлайн-оракул (тести без живої
  мережі)?». Якщо тести ходять у мережу — петля thrash. Можна додати рядок у `doctor.js`
  (WARN, не блок) — але тільки якщо реально болітиме двічі. Поки що — просто правило в конституції
  проекту (вже зашито в constitution бота §I).
- **C. Нічого більше.** Не чіпати elt-code роутер (71 рядок — правильно). Не повертати суддю в
  гарячий шлях.

## Частина 3 — Стратегія безкоштовної v2 (головне)

### Ключове відкриття (чому платний існує)
YouScore/OpenDataBot продають **одну річ**: **індекс за кодом сторони** (ЄДРПОУ → рішення). Сирий
ЄДРСР (`reyestr.court.gov.ua`) цього НЕ вміє + має капчу проти «викачування» (бачив живьём:
*«Введіть суму цифр... захист від викачування»*). Стара free-петля обходила це **чужими злитими
ключами OpenDataBot** — нелегально (штраф 100k грн, оферта п.5.20) і крихко (ключі ротуються).

### Рішення (перевірене доказами 2026-07-06)
Будувати **свій** індекс за кодом із **офіційного дневного дампу ЄДРСР** на data.gov.ua
(видавець — Державна судова адміністрація, ZIP, оновлення 1×/день). Це те, що агрегатори продають.

| Ланка | Доказ (живьём цієї сесії) |
|---|---|
| Офіційний дамп ЄДРСР існує | `data.gov.ua` → «Єдиний державний реєстр судових рішень за 2024/2025/2026 рік», ДСА, ZIP, 1×/день |
| Enrich за ID працює безкоштовно | fetch `/Review/29251985` → повний текст (Ощадбанк, «стягнення заборгованості»), обхід капчі print-view |
| Капча на live-скрейпінгу реальна | у відповіді ЄДРСР видно anti-scraping елемент — ось чому оригінал повільний |
| ЄРБ (виконавчі провадження) | офіційний API `erb.minjust.gov.ua` — аналог платного `/enforcement` (⚠ періодично down) |

Архітектура: **дамп → парсер кодів сторін → локальний SQLite-FTS індекс → миттєвий запит →
enrich за ID тільки для збігів → dedup/region/блокування/Telegram.** Live-скрейпінг — тільки
fallback за промаху, з circuit breaker. Деталі — `sudovi-fast/specs/001-*/spec.md`.

### Стек
Рекомендація — **Go** (IO-конкурентність, один статичний бінар вбиває біль Python-3.10.6-піннінгу
оригіналу, `goquery`+`go-sqlite3`). Альтернатива мінімального ризику — **Python-async** (реюз
доменної логіки оригіналу 1:1). Рішення винесене в слайс **T002**, не нав'язане.

### Що переноситься з оригіналу 1:1 (не переписувати з нуля)
- `extract_sum` (6 регекс-патернів) — робочий, портувати.
- 3 правила блокування (`processor.py`) — портувати з тестом-дзеркалом.
- `region_filter.py`, формат Telegram, `isolated_runtime` (dry-run) — портувати.
- Історичні `output_free/decisions_*.json` — золотий набір для аудиту паритету (T014).
