# spec — мост specify ↔ loop (одна система)

> Пример вывода **Режима 0** `/elt` (план-шаг). Спека читается судьёй как рубрика scope.

## Проблема
Харнесс имеет две несоединённые половины: передняя (генерация `spec.md`/`tasks.md`) и
задняя (петля `elt.js`+`elt-loop.ps1` грызёт `[ ]`). Общее — только формат файла, и мост
ручной: проекты, крутившие петлю (AWE4/Fasoli), имели рукописный `tasks.md` без `spec.md`.
`/elt` не умеет создавать план; `project-bootstrap` (наш доктор) переднюю половину **явно
откладывает**. Итог — «полного цикла через specify» как единого пути нет.

## Решение (вариант B — одна система, без усыновления spec-kit)
Передняя половина = тонкий **план-шаг внутри `/elt`**, а не второй движок. Использует уже
готовое: `constitution` (harness-method), `grill-me` (=clarify), судья (=analyze), наш формат
`tasks.md` (парсит `elt.js`). spec-kit не тащим — он дублирует это.

## Объём (scope)
- Режим 0 в `/elt`: крупная задача без плана → создать `specs/NNN/{spec,tasks}.md` → Режим 1.
- Судья (в сессии и в драйвере) получает `constitution.md` + `spec.md` как рубрику scope.
- Доктор диагностирует «half-cycle»: оракул взведён, но `specs/` не создавался.
- `project-bootstrap`: передняя половина для код-домена + live-fire полного цикла в closeout.

## Критерии приёмки
- `node tools/doctor.test.js` → PASS (включая новый кейс half-cycle).
- `node --check tools/doctor-core.js` чисто; `elt-loop.ps1` парсится PS-парсером, BOM на месте.
- `/elt` SKILL.md содержит Режим 0 и строку «судья получает spec»; версия 2.2.0.
- `project-bootstrap` SKILL.md больше не «откладывает» переднюю половину для кода; версия 1.7.0.

## Вне scope (не делать)
- Не усыновлять spec-kit `/speckit-*` как второй исполнитель.
- Не вводить `plan.md` — ни один тул его не читает (ceremony). Только `spec.md` + `tasks.md`.
- Не менять механику `elt commit`/оракула/петли — работа только соединительная.
- Не гонять автономный драйвер по этому репо (грязное дерево: `elt commit` = `git add -A` затянет мусор).
