# spec — ELT Fleet: режим мульти-CLI оркестрации

> Дизайн и ресерч: `.planning/ELT-FLEET-DESIGN.md` (читать судье как рубрику вместе с этим файлом).

## Проблема

elt-loop последовательный и одно-провайдерный (claude): планы с независимыми слайсами
ждут в очереди, а исчерпание Claude-лимита останавливает ВСЮ работу. Нужен режим,
который параллелит независимые слайсы через несколько CLI-агентов (claude / codex /
agy — Antigravity/Gemini по подписке) и переносит нагрузку при лимитах — не ломая харнесс.

## Решение (объём)

Оркестратор-код `tools/fleet/fleet.js` (node, без deps, Node 18+):
- N воркеров = headless-процессы (`claude -p` / `codex exec` / `agy -p` — Antigravity/Gemini
  по подписке, промпт через STDIN, hard-таймаут, пустой stdout при exit 0 = fail), каждый
  в своём git worktree (`.fleet-wt/<Tid>`, ветка `fleet/<Tid>`);
- параллелятся только слайсы `[P]` с непересекающимися `[files:]`-глобами (теги
  размечает план-шаг);
- гейт слайса неизменен: оракул → судья (claude sonnet, REJECT-default) → `elt commit`
  в worktree; merge в интеграционную ветку — последовательной очередью со smoke-оракулом;
  `[X]`-марк ставит оркестратор после merge;
- роутер: size-тег → цепочка провайдеров (`fleet.json`), failover по сигнатурам
  лимитов (429/quota/…) с cooldown и ledger-записью в run-log.jsonl;
- kill-switch `.harness/STOP`, resume по claims; видимость: `fleet status` +
  wt-панели с хвостами логов (обёртка `tools/elt-fleet.ps1`).

## Критерии приёмки (v1 done)

1. Интеграционный прогон на фейк-CLI-стабах: 2 воркера, ≥3 [P]-слайса, 1 искусственный
   merge-конфликт — все слайсы закрыты через `elt commit`, конфликтный дожат serial,
   `node --test tools/fleet/` зелёный.
2. Live-fire бенч (T016): план с 4+ честными [P]-слайсами, `fleet run --workers 2`
   закрывает все; wall-clock ≥1.5× быстрее последовательного baseline; судья вызван
   на 100% код-слайсов (проверка по run-log); 0 коммитов мимо `elt commit`.
3. Failover: стаб/инъекция 429 у провайдера → слайс уезжает на следующего в цепочке,
   ledger фиксирует `failoverFrom`, прогон завершается зелёным.
4. `.harness/STOP` посреди прогона: воркеры гаснут ≤30с, повторный `fleet run`
   добирает остаток без потери закрытых слайсов (resume по claims).
5. `doctor` видит fleet-хвосты: stale claims, брошенные worktrees, недоступный CLI.

## Вне scope

- PTY-кукловодство интерактивных TUI и свой терминал-клиент (headless покрывает;
  эскейп-хатч — WezTerm cli / Desktop Commander, отдельным решением при нужде).
- Кросс-машинный/облачный fleet, A2A/MCP-обмен между воркерами.
- Изменение инвариантов `elt.js` (оракул/судья/commit-гейт) и elt-loop.ps1.
- UI-дашборд (wt-панели достаточно), автотюнинг числа воркеров, «умный» LLM-роутинг.
- Экономия суммарных токенов как цель (см. дизайн §7 — цель: время + разгрузка
  Claude-бюджета).
