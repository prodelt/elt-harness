# 024 — Харнес работает не только на машине автора

## Проблема

ELT продаёт одно обещание: «сидит между агентом и коммитом и не пускает непроверенную
работу». На Linux и macOS это обещание **не выполняется ни в одном из трёх своих звеньев**,
и ни одно из трёх не сообщает об отказе.

```
$ node tools/elt.js oracle          # первый шаг цепочки гейта из CLAUDE.md
elt oracle: exit 1 (0s)             # ноль секунд, ноль строк причины
```

Полная картина замера (детали и воспроизведения — `audit.md`, ссылки вида E-n ниже):

| звено | что заявлено | что на POSIX |
| --- | --- | --- |
| механический оракул | `exit 0` — условие закрытия слайса | `exit 1 (0s)`, пустой вывод: `shell: "powershell"` из поставочного конфига (**E11**) |
| замок на коммит | «managed pre-commit gate» | хук закоммичен режимом `100644`, git печатает `hint:` и **коммитит** (**E2**) |
| собственный сьют | `112/112` в бейдже README | `110/112`, exit 1 (**E4**) |

Это не три бага. Это один факт: **харнес никогда не исполнялся вне машины автора.** Тот же
факт даёт доктора, который на чужом чистом репозитории выдаёт 9 FAIL и советует
несуществующую команду `init-project` (**E6**); аудит агентской поверхности, который на
Linux безусловно зовёт `cmd.exe /c where` и поэтому всегда врёт (**E16**); планировщик
retro-label, у которого нет ветки кроме `Register-ScheduledTask` (**E16**); и путь памяти
`~/.claude/projects/C--/memory/`, выведенный из буквы диска (**E16**).

### Второй корень: пруф о дереве привязан к форме вывода git, а не к содержимому

`treeHash()` (`tools/elt.js:293`) складывает в sha256 строки `git status --porcelain -uall`
дословно, вместе с колонкой статуса. Колонка меняется от индексации:

```
до  git add -A:   " M f.txt"   "?? g.txt"     ← здесь пишется пруф
после git add -A: "M  f.txt"   "A  g.txt"     ← здесь его сверяет хук
```

`elt commit` делает `git add -A` (`:2078`) перед `git commit` (`:2084`), а хук пересчитывает
хеш уже после (`:1881`). **Совпадения не будет никогда** (**E1a**). В режиме
`verify: "background"` — а его ставит по умолчанию сам `project-bootstrap apply` — `elt commit`
при включённом хуке непроходим в принципе; тот же слайс с `git config --unset core.hooksPath`
коммитится с exit 0.

Тот же корень даёт вторую поломку: `git()` (`:67`) делает `.trim()` всего stdout, срезая
ведущий пробел ПЕРВОЙ строки, после чего `line.slice(3)` (`:331`) отъедает символ от пути, и
`planPath()` не узнаёт файл плана (**E1b**). Нормализация маркера задачи — единственное, ради
чего `hashTaskMarksNormalized` существует, — не срабатывает ровно в своём главном случае.

Следствия каскадом: `project-bootstrap apply --apply` оставляет чужой проект в дедлоке, где
`elt commit` требует подписи спеки, а `elt spec approve` не может закоммитить подпись через
им же установленный хук (**E7**); неудачный `elt commit` оставляет задачу помеченной `[X]` и
ветку созданной, а повтор отвергается как `closed-task`, причём имя ветки содержит дату —
одна попытка на задачу в сутки (**E8**).

### Третий корень: гейт доверяет слоям, которые сам не проверил

- **Кэш оракула отдаёт ложные попадания.** `computeEntry` зовётся без `scanDirs`, дефолт —
  `['tools']`, а корней сьюта три. Правка `bin/l0.js` не сдвигает ключ `bin/l0.test.js`:
  тест не гоняется, оракул печатает `N/N passed` и exit 0 на сломанной точке входа плагина
  (**E3**). Ровно то, ради запрета чего `bin/` и сделали корнем в 019/T011.
- **Конфиг валидирует 8 полей из 33.** `redProof: "OFF"` включает контур, `specApproval: "no"`
  включает гейт, `batch: "three"` тихо становится 3, `shel` игнорируется молча (**E12**).
  Файл читают 14 независимых точек, каждая со своим `try/catch`-дефолтом.
- **Проверки, которые не могут сработать.** `unresolvedReview` фильтрует по полю `resolved`,
  которого никто не пишет; гард `--push` читает `commitHash` у сертификатов, несущих `commit`
  (**E9**). Обе молчат — и обе выглядят как работающая защита.
- **Песочница для чужих паков объявлена, но не подключена.** `capability-broker.js` (298 стр.)
  назван в `docs/ARCHITECTURE.md:127` границей безопасности и не требуется ни одним
  production-модулем (**E13**).

### Четвёртый корень: продукт закрыт для чужого

Язык — не оформление, а требование валидатора: `SPEC_REQUIRED_SECTIONS` (`elt.js:489`) — шесть
русских заголовков, обхода в конфиге нет, англоязычная команда не напишет проходящую спеку
(**E5**). 62 % строк `console.error`/`die()` — кириллица; всё, что грузится в рантайме
(`skills/elt/SKILL.md`, `commands/*.md`, `agents/*.md`, `CLAUDE.md`) — кириллица, при
английском README. Шестая линза ревью ломает харнес целиком (`review-runtime.js:97`:
`lenses.length !== LENS_NAMES.length` → `dead` → каждый слайс заблокирован), провайдер вне
трёх зашитых невозможен (**E13**). Нет `package.json` — ни `engines`, ни `npm test`, ни
версии, ни способа быть зависимостью (**E10**).

Три пути новичка пройдены живьём. **Зелёного гейта не даёт ни один** (**E6**).

### Пятый корень: «зелёный» бывает без единого исполненного теста

Три независимых пути дают `exit 0` там, где не проверено ничего.

- **Кэш оракула — не доказательство, но неотличим от него.** `.harness/oracle-cache.json`
  гитигнорен, а `treeHash` строится из `git status`, `git diff HEAD` и содержимого untracked —
  игнорируемого файла нет ни в одном источнике. Записать в кэш ключи, посчитанные на СЛОМАННОМ
  дереве, — и оракул печатает `65/65 passed in 0.0s`, exit 0, не исполнив ни одного теста;
  `writeOracleProof` штампует зелёный пруф, привязанный ровно к этому дереву, а
  `elt commit --skip-oracle` его принимает (**E17**).
- **Зависший судья выходит нулём.** `withJudgeTimeout` делает `timer.unref()`
  (`elt-verify-bg.js:266`) — таймер не держит event loop, Node осушает цикл и выходит ДО
  срабатывания гарда. `try/finally` не выполняется: ни run-log, ни строки очереди, ни
  `bg-red`; процесс возвращает 0 (**E18**). Та же строка — корневая причина красноты на
  Linux: удаление её одной даёт `49/49 pass, exit 0`.
- **Сьют оракула фабрикует ctx7-пруфы в гейтуемый проект.** `context7-cli.test.js` гоняет
  `appendCtx7Proof` фейковыми раннерами с `cwd: ROOT`. Живой реестр репозитория — 35 строк,
  100 % фабрикации; `ctx7Covered()` матчит подстрокой, поэтому L0 не заблокирует импорт
  `ai`, `mcp`, `agents`, `playwright`, `cli`, `vercel` (**E19**).

### Шестой корень: серверный агент не может ни переспросить, ни посмотреть в лог

Харнес предназначен в том числе для **агентов на автоматических серверах**. Там нет человека,
который прочитает подсказку. Тот же список дефектов меняет цену:

| находка | у человека | у серверного агента |
| --- | --- | --- |
| `exit 1 (0s)` без причины (**E11**) | 10 минут разбора | петля перезапусков: причины нет в выводе |
| зависший судья → exit 0 (**E18**) | замечен на глаз | непроверенный коммит уезжает молча |
| `verdict: dead` без причины и пути к логу (**E6**) | посмотреть лог руками | нечего логировать |
| подделываемый кэш (**E17**) | нужен злой умысел | достаточно битого тома: `ran = 0` = «всё зелено» |
| код 4 = четыре разных отказа (**E10**) | видно из текста | ветвление невозможно |
| `--json` у 9 команд из 26 | читает глазами | на `commit`/`gate`/`judge run` парсить нечего |
| Linux — единственная серверная платформа | обходится Windows-машиной | обхода нет |

Живой отказ провайдера на сервере под root: `--dangerously-skip-permissions cannot be used
with root/sudo privileges for security reasons`. Строка лежит в логе провайдера и не
печатается никогда, а поле `judgeLog` доводится до `elt.js:1671` и там теряется.

## Решения

Спека закрывает то, что делает харнес НЕработающим у чужого, и те дыры гейта, из-за которых
«зелёный» не означает «проверено». Косметика, перевод и декомпозиция — отдельные спеки
(см. «Вне scope»), потому что смешивать фикс замка с переименованием строк значит потерять
и то и другое в одном диффе.

1. **Платформа выбирается, а не предполагается.** Один диспетчер шелла
   (`tools/shell-run.js`) вместо пяти копий; `shell` входит в валидацию закрытым списком;
   отсутствующий интерпретатор даёт громкий отказ с именем шелла и подсказкой, а не
   `exit 1 (0s)`. Дефолт выводится из `process.platform`, а не пишется в поставку. Поставочный
   `.harness/harness.json` перестаёт быть личным конфигом Windows-машины.

2. **Пруф о дереве считается от содержимого.** `treeHash` перестаёт хешировать колонку
   статуса git: путь и класс изменения (tracked-modified / untracked / deleted) — да, форма
   вывода — нет. Разбор `--porcelain` идёт по фиксированной раскладке `XY<пробел>path` без
   `.trim()` всего потока. Это чинит E1a и E1b одной правкой и снимает дедлок E7. Регрессия
   обязана краснеть на СТАРОМ коде: пруф, снятый до `git add -A`, сверяется после него.

3. **Замок либо висит, либо честно говорит, что не висит.** `.githooks/pre-commit`
   получает режим `100755` в индексе. Класс шире одного файла — ни один файл репозитория
   не имеет исполняемого бита при 24+ shebang'ах, — поэтому вводится проверка поставки, а не
   правка одного пути. `elt doctor` отдельной строкой отвечает на вопрос «замок включён и
   исполним?», потому что `hint:` от git не читает никто.

4. **Кэш оракула перестаёт врать.** `scanDirs` = те же `TEST_ROOTS`, что и у обхода;
   `RUNNER_VERSION` включает `elt-oracle-select.js`, откуда берутся правила замыкания.
   Регрессия: правка `bin/*.js` обязана сдвигать ключ соответствующего теста.

5. **Named oracle зелёный на Linux.** `elt-verify-bg.test.js` — висящий промис
   (`new Promise(() => {})`) заменяется на управляемое ожидание; `benchmarks/.../runner.test.js`
   при отсутствии `pytest` даёт честный skip с причиной, а не красный. Оракул, красный из-за
   ненаписанной зависимости, обучает игнорировать красноту.

6. **Конфиг — контракт, а не набор надежд.** Схема с закрытым списком полей: неизвестный
   ключ и значение вне типа — ошибка `elt init`/`elt doctor`, а не другое поведение гейта.
   Одна точка чтения с кэшем на процесс вместо 14 независимых `JSON.parse`.

7. **`package.json` появляется.** `engines.node`, `scripts.test` → полный оракул, `version`
   синхронизирована с остальными пятью местами через `version-check.js`. Без него харнес не
   может быть ни зависимостью, ни воспроизводимой установкой.

8. **Мёртвые проверки либо работают, либо снимаются.** `unresolvedReview` и гард `--push`
   чинятся по правильному полю; гард `--push` дополнительно сравнивает короткий sha с
   коротким, иначе фикс переключит его в «всегда блокировать».

9. **Одна точка расширения открывается — набор линз.** `review-runtime` перестаёт требовать
   РОВНО пять файлов и начинает требовать «все объявленные присутствуют». Шестая линза
   перестаёт означать мёртвого судью. Реестр провайдеров и песочница паков — отдельная спека:
   у них есть проектное решение, которого нет у линз.

10. **Кэш перестаёт быть доказательством.** Оракул-пруф несёт, сколько файлов ИСПОЛНЕНО и
    сколько взято из кэша. `ran === 0` не может быть основанием ни для `--skip-oracle`, ни для
    прохождения `elt gate`: «ничего не гоняли» и «всё зелено» перестают быть одной строкой.
    Кэш переезжает под `.git/elt/`, где его не примут за часть проекта.

11. **Зависший судья фейлится закрыто.** Снимается `unref()` у гарда таймаута — одна строка,
    которая чинит и молчаливый `exit 0` на сервере, и красный сьют на Linux. Плюс
    `beforeExit` в ветке `require.main`: выход без терминальной записи становится `bg-dead`,
    а не нулём.

12. **Отказ называет причину машине, а не человеку.** `judgeLog` печатается на пути отказа;
    `elt commit`, `elt gate` и `elt judge run` получают `--json` с полем `reason`; коды
    выхода разводятся так, чтобы автоматика могла ветвиться, и документируются в
    `docs/USAGE.md`. Сьют перестаёт писать в дерево гейтуемого проекта: `context7-cli.test.js`
    работает в `mkdtemp`-фикстуре, а `ctx7Covered` матчит пакет точно, а не подстрокой.

## Вне scope

**Не входит и почему:**

- **Перевод пользовательской поверхности на английский.** Это не строковая замена: шесть
  заголовков в `SPEC_REQUIRED_SECTIONS` — семантическое требование, и его снятие меняет формат
  всех 24 существующих спек. Отдельная спека 025; здесь только выносится сам список в конфиг,
  чтобы перевод стал возможен без правки кода.
- **Декомпозиция `tools/elt.js`** (2 254 стр., 0 экспортов, 18 command-блоков, `commit` = 305
  строк inline). План готов и лежит в `audit.md`, но перекладывание 900 строк в одном диффе с
  фиксом замка гейта не поддаётся ревью. Спека 026, шаг за шагом под существующими 29
  spawn-тестами как страховочной сеткой.
- **Удаление ≈6 000 строк неподключённого кода** (**E14**). Каждый файл требует отдельного
  решения «подключить или снять», а `capability-broker` — ещё и проектного: он объявлен
  границей безопасности. Смешивать это с фиксами гейта нельзя.
- **Реестр провайдеров, монорепо, SARIF/JUnit, CI-action, документация 33 полей конфига,
  `elt spec new`.** Всё это — новая функциональность. Она не имеет смысла, пока харнес не
  запускается у того, кому она предназначена.
- **Замена подстрочной impact-выборки на разбор `require()`** (**E15**: правка `elt.js`
  задевает 68 % файлов, слой вырождается). Это переписывание алгоритма выборки с собственным
  риском ложных пропусков — то есть ровно тот риск, который эта спека закрывает в кэше.
  Отдельно и с собственным замером.

## Критерии приёмки

- **AC1.** `node tools/elt.js oracle` на Linux и macOS отрабатывает полный оракул и
  возвращает его настоящий код. Отсутствующий интерпретатор даёт отказ, называющий шелл и
  способ его сменить, а не `exit 1 (0s)`.
- **AC2.** `node tools/elt-oracle-runner.js --full` — exit 0 на Linux (Node 20/22/24) и на
  Windows. Ни один тест не краснеет из-за незадекларированной системной зависимости.
- **AC3.** `elt commit` проходит при включённом `core.hooksPath .githooks` в режиме
  `verify: "background"`. Регрессия краснеет на коде до фикса.
- **AC4.** `git ls-files -s .githooks/pre-commit` → `100755`; тест поставки краснеет на любом
  файле с shebang и режимом `100644`.
- **AC5.** Правка любого файла под `bin/` или `benchmarks/` сдвигает ключ кэша
  соответствующего теста; правка `tools/elt-oracle-select.js` инвалидирует кэш целиком.
- **AC6.** `validateHarnessConfig` отвергает неизвестный ключ и значение вне типа; названы
  ключ и ожидаемое. `shell` — в списке валидируемых.
- **A7.** `package.json` существует, `engines.node` совпадает с проверкой `bin/doctor.js`,
  `npm test` гоняет полный оракул, `version` сверяется `version-check.js`.
- **AC8.** Шестая линза в `lensesDir` не делает судью мёртвым; отсутствие объявленной линзы —
  делает.
- **AC10.** Оракул-пруф содержит `ran` и `cached`; `ran === 0` отвергается `elt gate` и
  `--skip-oracle` с явной причиной. Подделанный кэш не даёт зелёного коммита.
- **AC11.** Зависший судья в фоне даёт ненулевой выход, строку run-log и строку очереди.
  Регрессия — та самая `T007`, которая сейчас виснет.
- **AC12.** Полный прогон оракула в свежем клоне не создаёт в дереве ни одного файла.
- **AC13.** `elt commit`, `elt gate`, `elt judge run` принимают `--json`; на отказе судьи
  печатается путь к логу провайдера и первая строка причины.
- **AC9.** `unresolvedReview` убывает при закрытии строки очереди; гард `--push` срабатывает
  на сертификате от чужого коммита и не срабатывает на своём.

## User stories

- **Как разработчик на macOS, поставивший плагин,** я хочу, чтобы первая же команда гейта
  либо работала, либо назвала причину, — сейчас она отвечает `exit 1 (0s)`, и отличить
  «оракул красный» от «нет powershell» невозможно.
- **Как команда, прогнавшая `project-bootstrap apply`,** я хочу иметь возможность закоммитить
  хоть что-нибудь, — сейчас `elt commit` отвергает собственный пруф, а обычный `git commit`
  заблокирован установленным хуком, и выхода нет ни в одном документе.
- **Как человек, доверяющий зелёному оракулу,** я хочу, чтобы «112/112 passed» означало, что
  112 тестов исполнились, — сейчас правка точки входа плагина даёт ту же строку, не запустив
  ни одного из них.
- **Как контрибьютор,** я хочу, чтобы `--full` был зелёным сразу после `git clone` на моей
  платформе, — иначе я не могу отличить свою поломку от унаследованной.
- **Как автор форка,** я хочу добавить шестую линзу ревью и не сломать судью целиком.

## Риски

- **Смена формы `treeHash` инвалидирует все существующие пруфы.** Любой незакрытый слайс с
  записанным оракул-пруфом получит `stale` после обновления. Это осознанно: старые пруфы
  посчитаны по правилу, которое доказано неверным. Смягчение — пруф несёт версию схемы, и
  пруф старой версии отвергается с явной причиной «перепрогони оракул», а не с загадочным
  «не про это дерево».
- **Расширение кэша на `bin/` и `benchmarks/` увеличивает замыкание и снижает долю
  попаданий.** Прогон станет медленнее ровно на те тесты, которые до сих пор не гонялись.
  Это не регресс производительности, а возврат к честной цене; альтернатива — зелёный гейт
  на непроверенном коде.
- **Строгая валидация конфига сломает существующие проекты с лишними ключами.** Поэтому
  первый релиз строгости печатает предупреждение с полным списком незнакомых ключей и
  ошибается только на значениях вне типа; отказ на неизвестный ключ включается следующей
  минорной версией, а не этой.
- **Skip вместо красного у `benchmarks/.../runner.test.js` уменьшает охват там, где
  `pytest` не стоит.** Смягчение: skip обязан называть причину и заявленную зависимость, а
  CI обязан ставить `pytest` и потому получать полный охват — то есть в CI ничего не
  ослабевает, ослабевает только у контрибьютора, у которого этот тест сейчас просто красный
  и бесполезный.
- **Исполняемый бит не переживает checkout на Windows без `core.fileMode`.** Git хранит бит
  в индексе и восстанавливает его при checkout на POSIX; на Windows он не наблюдаем и не
  нужен — там хук вызывается через интерпретатор. Проверка поставки смотрит индекс
  (`git ls-files -s`), а не файловую систему, поэтому одинаково работает на обеих платформах.
- **Линзы: смена `!==` на «все объявленные присутствуют» ослабляет проверку.** Именно
  поэтому вводится ЯВНЫЙ список требуемых линз, а не молчаливое «сколько нашли, столько и
  ладно»: отсутствие объявленной линзы обязано оставаться мёртвым судьёй.
