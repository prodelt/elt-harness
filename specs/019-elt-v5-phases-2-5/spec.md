# 019 — ELT v5: фази 2–5 (ревʼю по офіційному рецепту → зрізання коду → плагін → реліз)

## Проблема

Фази 0 і 1 концепції `.planning/ELT-V5-CONCEPT-2026-08-22.html` закриті: гігієна зроблена,
підпис спеки знято з критичного шляху (спека 018, D4/D7/D11/D15 закриті), доля комітів через
харнес у цьому репозиторії — 62,0% (49/79) проти 59,5% до 018. Лишилися чотири фази, і в
кожної з них свій незакритий біль:

- **Шум ревʼю.** Сигнал/шум блокуючих вердиктів = 1:7 — сім із восьми блокувань хибні.
  Механізм шуму назвали поіменно: D9 (штраф за згенерований `package-lock.json`),
  D15 (файл, який пише сам харнес, вважається порушенням зони), D19. Причина спільна —
  немає єдиного списку «це належить харнесу», кожна перевірка тримає свій.
- **Батч не працює.** D13 — зона батча читає лише ПЕРШЕ входження `[files:]`
  (`.match()` без прапорця `g`), тому будь-який коміт на N>1 задач отримує `out-of-scope`
  на файлах задач 2..N. D14 — поріг `diff-size` = 400 рядків константою, не масштабується на
  число задач. Разом вони роблять задекларований батч-режим непрохідним.
- **Свого коду 31 752 рядки.** З них цілі підсистеми не мають користувача: `fleet/`,
  PowerShell-драйвери, дві синхронізації (`sync-bin.js` копіює рантайм у `~/.claude/bin`,
  `sync-agent-surface.js` — скіли у три CLI). Штатні субагенти Claude Code і `--worktree`
  роблять те саме без власного двигуна.
- **Дистрибуція ручна.** Сьогодні харнес живе копією в `~/.claude/bin` — з цього народився
  цілий клас дефектів (deploy-замикання, D16, D18: правка є в `tools/`, немає в копії).

## Решения

Виконати фази 2–5 концепції в один прохід, чотирма батчами по 5 задач.

- **Фаза 2 — ревʼю по офіційному рецепту.** Пʼять лінз як окремі субагенти, оцінювач
  упевненості на `claude-haiku-4-5-20251001`, відсічка 80, явний список типових хибних
  спрацювань. Один спільний модуль «належить харнесу» для гейта зон, `diff-size` і ревʼюера —
  D9, D15, D19 закриваються однією правкою. Сюди ж D13/D14: без них батч по 5 задач
  непрохідний, а саме батчами йде решта спеки.
- **Фаза 3 — зрізання.** Видаляються `tools/fleet/**`, PowerShell-драйвери
  (`elt-loop.ps1`, `elt-drive.ps1`, `elt-fleet.ps1`, `elt-selfheal*.ps1`), `approval-guard.js`
  (він жив тільки для двох цих викликів), `sync-agent-surface.js`, codegraph-інтеграція.
  Паралельність — штатними субагентами і `--worktree`.
- **Фаза 4 — плагін.** Структура з розділу 08 концепції, свій маркетплейс, CI на
  `windows-latest` і `ubuntu-latest`, `AGENTS.md` генерується з єдиного файлу інструкцій.
  `sync-bin.js` і deploy-замикання знімаються ОСТАННІМИ — тільки після того, як установка
  плагіна в чистому проєкті доведена зеленою, інакше 12 чужих проєктів лишаються без харнеса.
- **Фаза 5 — реліз.** README з чесними числами «до і після», CHANGELOG, MIT, тег; реєстр
  дефектів публікується розділом README — система заявляє про свої відомі проблеми сама.

## User stories

- Як власник харнеса, я хочу, щоб блокування означало дефект, а не шум: сім хибних блокувань
  із восьми навчають ігнорувати вердикт узагалі.
- Як власник, я хочу закривати задачі пачками по пʼять, а не по одній, бо кожен окремий зріз
  коштує повного прогону оракула і судді.
- Як власник, я не хочу тримати другий двигун паралельності: у Claude Code вже є субагенти.
- Як користувач у чистому проєкті, я хочу `claude plugin install elt@elt` і робочий харнес
  без ручного копіювання в `~/.claude/bin`.

## Критерии приёмки

- **Фаза 2:** на 20 діффах поспіль сигнал/шум ≥ 1:1; жодного вердикту по `package-lock.json`,
  `approval.json`, `review-queue.jsonl`; батч-коміт на 5 задач проходить зону і `diff-size`
  (регреси на D13/D14).
- **Фаза 3:** свого коду ≤ 5 000 рядків (`wc -l` тією ж командою, що дала 31 752);
  повний оракул зелений; жоден сценарій `PLAYBOOK.md` не втрачено мовчки — кожен або має
  заміну штатним засобом, або явно записаний як знятий.
- **Фаза 4:** у чистому проєкті `claude plugin install elt@elt` → `/elt-doctor` зелений
  без ручних кроків; CI зелений на обох платформах.
- **Фаза 5:** установка з чистої машини по README без звернення до автора; відкритих
  блокуючих дефектів нуль, решта висить як issue.

## Риски

- **Видалення `fleet/` і драйверів рве чужі проєкти,** якщо вони кличуть ці шляхи. Помʼякшення:
  перед видаленням — інвентар усіх посилань, після — гучна відмова з маршрутом на `elt`.
- **`~/.claude/bin` — жива залежність 12 проєктів.** Тому `sync-bin.js` знімається останнім
  завданням фази 4, після зеленої установки плагіна, а не разом із рештою зрізання.
- **Linux у CI — новий ґрунт.** Код писався під Windows; жорсткі `C:\`, `powershell.exe`,
  `.cmd` і CRLF доведеться знайти поіменно, інакше `ubuntu-latest` червоний назавжди.
- **Пʼять лінз субагентами дорожчі за одного суддю.** Помʼякшення: оцінювач на haiku,
  відсічка 80, лінзи запускаються паралельно.
- **Спека виконується батчами по 5 під гейтом, який сама ж чинить.** Перший батч іде з
  ще живими D13/D14 — саме тому їх фікс стоїть у ньому першим завданням.

## Вне scope

- Переписування `elt commit` з `git add -A` на пофайловий коміт — окрема стіна, окрема спека.
- Зміна складу механічного оракула.
- `rtk` як залежність — виміряно (≈3,8% контексту), у реліз не входить.
