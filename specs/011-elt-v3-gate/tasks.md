# Дополнение 01.08.2026 — по сверке живого кода со схемами артефакта

Источник: `ELT v3 — протокол замера и три схемы харнесса.html` (схемы A и C, §04–§07), сверка
проведена по коду, не по документам. Три вывода сверки, из которых выведены слайсы ниже:

1. **Схема A реализована по слоям, но не как лестница доверия.** `verify` снят (T001), однако в
   живой цепочке по-прежнему **четыре последовательных вето**: `L0.verdict → grounding → судья →
   red-proof`. Два из них выносят `block` вообще без качественного суждения. Формула артефакта
   `P(pass) = p₁ × p₂ × p_grounding` в живом контуре должна иметь четвёртый множитель — на схеме A
   `red-proof` из лестницы просто исчез. Пруф не теоретический: этим заблокирован T018.
2. **Граф несущим не стал.** Из трёх функций схемы C (scope / impact / риск) живёт одна — impact,
   и та на **обратном текстовом скане**: `codegraph affected` в этом репо возвращает пусто (замер
   T006). Scope — регулярка по `[files:]`, риск — глобы `hotPaths`.
3. **Эволюции нет, есть первое звено.** `harness-watch.js` = узел `D` схемы C, но
   `.harness/health.jsonl` — **одна запись за месяц**: его никто не зовёт. Звеньев `P → RG → AP/RB`
   и обратного ребра в гейт нет вовсе.
