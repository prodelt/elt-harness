# 022 — Публичный релиз: репозиторий как продуктовая поверхность

## Проблема

Независимый аудит 2026-08-26 поставил «оформление и продуктовая понятность» 4,5/10, а
«готовность для внешнего пользователя» — 2,5/10. Технические P0 к этому моменту уже закрыты
(`main` стал default-веткой, тег и релиз `v5.0.0` выпущены, CI позеленел, false green фонового
судьи закрыт 020/T007). Осталось ровно то, что аудит назвал release-management и packaging
defect, а не косметикой:

1. **Дерево — рабочий стол, а не поставка.** 610 из 876 отслеживаемых файлов — `.planning/` и
   `archive/`. Плюс корень описывает три разных продукта: `PROJECT.md` — про AMOS и `~/.amos`,
   `PLAYBOOK.md` — про ELT v3 с Fleet-эрой, `README.md` — про ELT v5.
2. **Личные данные в дереве.** 92 файла с абсолютными путями автора и именами сторонних
   проектов. Живых секретов нет, но публикация делает это необратимым.
3. **README раскрывает процесс разработки, а не продукт.** Первый экран после установки — KPI
   доли коммитов, размер собственного кода, невзятая цель ≤5 000 строк, реестр дефектов.
   Читателю нужно понять ценность инструмента, а не историю его постройки.
4. **Нет community-поверхности:** `CONTRIBUTING`, `SECURITY`, шаблонов issue/PR, метаданных
   `repository`/`homepage`/`bugs` в манифестах.

## Решения

Одна волна гигиены **без изменения поведения харнеса**. Ни одна проверка не меняет вердикт;
109/109 остаются зелёными до и после.

- Свести дерево к поставке; рабочие каталоги перевести в `.gitignore` — хуки продолжают писать
  в `.planning/`, git его не видит.
- Вычистить личные пути в дереве и в истории (`git filter-repo` по одному списку правил;
  полная неотредактированная история сохраняется в приватном архивном репозитории).
- Переписать README как обложку: проблема → что делает → доказательство → установка → границы.
  Все измерения с их оговорками — в `docs/EVIDENCE.md`, реестр дефектов — в `docs/DEFECTS.md`.
- Добавить community-файлы и метаданные манифестов.

## Вне scope

**Не входит:** разбиение `tools/elt.js` на модули (P2 аудита), capability-изоляция судьи для
Claude/agy (P1), non-zero exit при неуспешном `--push` (P1). Это правки поведения; они
требуют своих слайсов и своих регрессий.

## Критерии приёмки

- **AC1.** `node tools/elt-oracle-runner.js --full` — exit 0, охват не уменьшился.
- **AC2.** `node bin/doctor.js` — FAIL=0; `node tools/gen-agents-md.js --check` — exit 0.
- **AC3.** В отслеживаемых файлах нет абсолютных путей автора и имён сторонних проектов.
- **AC4.** Замок KPI сверяет снимок не только с текстом страниц, но и с деревом: расхождение
  «в снимке 108 тестов, в дереве 109» обязано краснеть. До этой задачи оно не краснело —
  README честно печатал устаревшее число, потому что сверялся со снимком, а не с реальностью.
- **AC5.** Ни одна ссылка в оставшихся `.md` не ведёт на удалённый файл.

## User stories

- **Как разработчик, впервые открывший репозиторий,** я хочу за тридцать секунд понять, что
  этот инструмент делает и подтверждено ли это цифрами, — чтобы решить, ставить его или нет,
  не читая историю его разработки.
- **Как пользователь, устанавливающий плагин,** я хочу одну команду установки и честный список
  того, чего инструмент НЕ делает, — чтобы не построить на нём то, что он не удержит.
- **Как автор,** я хочу опубликовать репозиторий, не отдав наружу абсолютные пути своей машины
  и имена клиентских проектов, — при этом не потеряв ни одного рабочего файла.
- **Как контрибьютор,** я хочу знать, какие проверки должны быть зелёными до PR, — чтобы не
  узнавать это из красного CI.

## Риски

- **Удаление файла, на который есть ссылка из кода, красит оракул.** Снижение: список удаления
  сверен грепом по `tools/`, `bin/`, `benchmarks/`; `packs/`, `graphs/`, `templates/`,
  `config/` и `agent-skills.lock.json` оставлены именно потому, что на них ссылается
  `bin/doctor.js` и тесты. Проверка — полный оракул до и после.
- **Слепая замена путей ломает фикстуры.** Реализовано: `tools/doctor.test.js` проверял, что
  один корень с двумя разделителями даёт один ключ, и замена разорвала пару — оракул это
  поймал, фикстура заменена нейтральной. `bin/doctor.test.js` намеренно держит абсолютный путь
  как FAIL-кейс; путь обезличен, но остался абсолютным.
- **Перенос чисел из README в docs выглядит как «число исчезло» и провоцирует ослабить замок.**
  Снижение: замок сверяет снимок с ОБЕИМИ страницами сразу и дополнительно с деревом.
- **Переписывание истории ломает клоны и теги.** Снижение: полная неотредактированная история
  сначала уходит в приватный архивный репозиторий; тег и релиз пересоздаются на новом SHA.
