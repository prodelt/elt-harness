# Состояние прогона — ПРОЕКЦИЯ, не источник

> Этот файл **генерируется** из журнала `.git/elt/graph-journal.jsonl`.
> Править его руками бессмысленно: следующий `elt run` перезапишет вывод, а авторитетом
> он не станет. Источник истины после cutover — журнал; до cutover — checkbox в `tasks.md`,
> approval-трейлеры и `run-log.jsonl` (эпоха `legacy-v1`).

Собрать актуальное состояние:

```powershell
node tools/elt.js run --json      # узел графа, законные события, следующий шаг
node tools/elt.js status          # то же + git, план и последний прогон
```

| Поле | Что означает |
|---|---|
| `epoch` | `legacy-v1` — авторитет у checkbox; `journal-v1` — у журнала (после `elt cutover`) |
| `node` | узел канонического графа: `recon → plan → build → landing → mirror → debrief → certified → publish` |
| `generation` | поколение батча; ремонт увеличивает его и делает proof прошлого поколения stale |
| `legal` | события, законные ЗДЕСЬ И СЕЙЧАС; всё остальное — `illegal-transition` |
| `next` | конкретный следующий шаг, чтобы маршрут не жил в памяти человека |
| `rejected` | события журнала, которые граф не принял — расхождение видно, а не сглажено |
| `statuses` | `open → built → landed → certified` по задачам, пересчитывается из журнала целиком |

Задача открыта/закрыта — это `statuses`, а не галочка: после cutover `tasks.md` хранит
**неизменное намерение**, а checkbox остаётся человекочитаемой проекцией.
