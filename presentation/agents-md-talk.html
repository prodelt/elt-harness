AGENTS.md — це коротка шпаргалка про ваш проєкт, написана звичайною мовою. AI-агент читає її й працює за вашими правилами, а не за здогадками. Спершу — коротка теорія, чому AI взагалі потребує такий файл. Далі: навіщо він вам, що всередині, як створити однією командою — і реальний приклад.

⓪ Спершу теорія · чому це взагалі потрібно

AI не має пам'яті між розмовами

Модель — як процесор без диска. Усе, що вона «пам'ятає», — це поточна розмова. Нова сесія — і сторінка чиста: про ваш проєкт вона знову не знає нічого.

🧠 Контекстне вікно = RAM

Швидка пам'ять поточної розмови. Але стирається щоразу: закрили чат — і все, що пояснювали, зникло.

💾 Файл у проєкті = диск

Лишається назавжди. Агент прочитав його на старті — і знову «в курсі» проєкту, хоч через місяць.

Тому знання про проєкт має жити у файлі, який агент читає на початку кожного завдання. Цей файл — AGENTS.md.

⓪ Спершу теорія · це не випадкова мода

«Пам'ять проєкту» — один із 12 компонентів будь-якого AI-агента

Дослідники розклали виробничого AI-агента на 12 частин: цикл, інструменти, обробка помилок, перевірки… Одна з них — довгострокова пам'ять: файли проєкту, які модель читає щоразу заново.

Це є в кожного серйозного інструмента. Різні назви — та сама роль: дати агенту контекст, що переживає перезапуск.

«Довгострокова пам'ять зберігається між сеансами: Anthropic використовує файли проєкту CLAUDE.md та автоматично створені MEMORY.md.»

① Навіщо це взагалі

AI не знає ваш проєкт. Щоразу пояснюєте заново.

Ви просите AI-агента щось зробити — а він не в курсі, як тут усе влаштовано. Якими командами запускати, як тестувати, якого стилю дотримуватись. Тож або він перепитує, або вгадує й помиляється.

Без файлу

  • Пояснюєте одне й те саме в кожній новій розмові
  • Агент вгадує команди й стиль — і часто мимо
  • Код виходить «не такий, як у нас у проєкті»

З файлом AGENTS.md

  • Написали правила один раз — лежать у проєкті
  • Агент читає їх сам на початку кожного завдання
  • Працює так, як ви очікуєте — з першого разу

Проблема не в тому, що AI «дурний». Просто йому ніхто не дав контексту. AGENTS.md — і є цей контекст.

Що це · проста аналогія

Це як інструкція для нового співробітника

Уявіть, що до вас у перший день виходить новачок. Ви не пояснюєте йому кожну дрібницю вголос щоразу — ви даєте онбординг-документ: ось як у нас усе влаштовано, ось інструменти, ось правила.

AGENTS.md — це той самий онбординг, але для AI-агента. Схоже на README, тільки README пишуть для людей, а цей файл — для програм-агентів, що працюють із вашим кодом.

«README — для людей. AGENTS.md — для агентів. Мета одна: дати короткий контекст про проєкт.»

Головна фішка · один файл для всіх

Раніше — зоопарк файлів. Тепер — один стандарт.

Не пишемо вручну — кажемо Codex /init

У сесії Codex запускаєте вбудовану команду /init. Codex сам сканує вашу кодову базу й генерує чернетку AGENTS.md у корені проєкту — за кілька секунд.

  • сам визначає стиль коду
  • сам знаходить команди збірки й тестів
  • сам описує структуру проєкту

Іноді Codex додає власні припущення. Побачили щось не так — трохи підкоригуйте. Це чернетка, а не догма.

codex — сесія в терміналі
› /init сканую структуру проєкту… читаю package.json, тести, конфіги… визначаю стиль і команди… ✓ створено AGENTS.md у корені проєкту › # готово — відкрий і перевір розділи

Кілька секунд — і файл із базовими правилами на місці.

🔧 У нас це робить один ритуал /project-bootstrap: генерує AGENTS.md одразу за еталоном (стислі розділи, без «журналу»), і дзеркалить його в CLAUDE.md та .gemini/GEMINI.md — один файл, три агенти.

Розбір · частина 1

Структура й команди — карта проєкту

🗂️ Structure — «де що лежить»

src/app/ — маршрути (auth/app/admin) src/components/ — UI: форми, shared, admin src/lib/ — Server Actions + zod supabase/ — міграції + Edge Functions

Агент одразу бачить, куди дивитись, і не блукає проєктом наосліп.

⚙️ Commands — «які кнопки натискати»

Dev: npm run dev (порт 3001) Тести: npm test (Vitest) Лінт: npm run lint ; npx tsc --noEmit

Найважливіше. Агент сам перевіряє свою роботу цими командами — без вгадування.

Дві прості речі — а агент уже орієнтується в проєкті як свій.

Розбір · частина 2

Стиль і тести — «пиши, як у нас»

✍️ Code style — правила оформлення

Іменування: camelCase функції, PascalCase компоненти Валідація входів через zod Жодних секретів у коді — тільки env

Codex дивиться, як проєкт уже організований, і виводить із цього правила. Код виходить однорідним, наче писала одна людина.

🧪 Testing — де тести й як їх писати

Нові тести → src/__tests__/ Файли: *.test.ts(x) Спершу падаючий тест, потім код Не скіпати «червоні» тести

Агент кладе нові тести туди, куди треба, і дотримується вашого підходу до перевірки.

Розбір · частина 3

Коміти й пастки — дисципліна та безпека

💾 Commit & PR — стиль роботи з Git

Коміт: <type>: <опис> (feat, fix, docs) PR: заголовок < 70 символів Не комітити: .env, node_modules, .next

Агент не лише пише код, а й охайно оформлює зміни — як прийнято у вашій команді.

⚠️ Gotchas — «граблі», на які не варто наступати

Робочий корінь — вкладена izi-tracker/ Auth лише через getUser(), не getSession() Деплой лише через vercel --prod

Найцінніше зі здобутого досвіду. Те, що ламається, якщо не знати — тепер агент знає наперед.

Оце і є «еталонна структура»: 8 коротких розділів — і будь-який агент розуміє проєкт із першого погляду.

Правило 1 · живий документ

Не «створив і забув» — оновлюй разом із проєктом

Проєкт росте й змінюється. Якщо файл застаріє — агент почне діяти за старими правилами й відхилятись від того, як ви працюєте зараз.

Онови, коли:

  • додали нову бібліотеку чи фреймворк
  • змінилася структура проєкту
  • змінилися команди тестування
  • змінилися правила розробки

Якщо не оновлювати:

Codex діятиме за першою версією файлу — старими командами й правилами. Замість помічника отримаєте агента, що тягне проєкт у минуле.

Правило просте: змінили щось важливе в проєкті — дописали рядок у AGENTS.md.

Правило 2 · закоміть у репозиторій

Додайте файл у Git — щоб і хмара його бачила

AGENTS.md варто закомітити й відправити в GitHub. Тоді його побачить не лише Codex у вас на комп'ютері, а й Codex Cloud під час віддалених завдань.

Коли ви даєте Codex завдання в хмарі, він автоматично шукає цей файл у репозиторії й бере як контекст. Файл у git = правила їдуть разом із проєктом, для всіх і всюди.

«Закомітьте AGENTS.md — і всі, хто працює з проєктом (люди й агенти, локально й у хмарі), гратимуть за одними правилами.»
