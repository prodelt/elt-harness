Файл agents.md у Codex CLI
Отже, друзі, у попередньому уроці ми говорили про команди, які вже вбудовані в інструмент Codex CLI.

Однією з таких команд була команда:

 
/init
 
Вона генерує для нас файл:

 
agents.md
 
у цьому проєкті.

Зараз ми скоро запустимо цю команду, але спочатку коротко поговоримо про те, що таке файл agents і навіщо його використовувати.

Що таке agents-файл
Файл agents.md можна уявити як щось схоже на README, але написане не для людей, а для coding agents, тобто агентів програмування, з якими ви працюєте.

Зазвичай цей файл знаходиться у вашому проєкті, найчастіше в кореневій папці.

Він пояснює агенту:

як працює ваша кодова база;
які команди потрібно використовувати для збірки й тестування;
якого стилю кодування ви дотримуєтеся;
як структурований ваш проєкт;
які правила та підходи важливо враховувати під час роботи з кодом.
По суті, це невелика шпаргалка, яка допомагає агенту краще вписатися у ваш робочий процес і писати код так, як ви очікуєте.

Як Codex використовує agents.md
Codex активно використовує файл agents.md.

Коли ви просите Codex щось зробити — локально або через Codex Cloud — він шукає цей файл у вашому проєкті.

Якщо файл існує, Codex бере інформацію з нього як контекст для ваших промптів і завдань.

Тобто все, що записано в agents.md, може впливати на те, як Codex розумітиме проєкт і як виконуватиме ваші інструкції.

Подібні файли в інших AI-інструментах
Якщо ви користувалися іншими AI-агентами для програмування, наприклад Claude Code або Copilot, ви, ймовірно, вже бачили схожі файли.

У Claude Code використовується файл:

 
claude.md
 
для інструкцій на рівні всього проєкту.

У Copilot використовується markdown-файл з інструкціями для Copilot, який виконує схожу функцію.

Усі ці файли мають подібну мету: вони дають агенту пам’ять і короткий контекст про проєкт.

Чим відрізняється agents.md
Особливість файлу agents.md полягає в тому, що його просувають як стандарт для різних AI-інструментів програмування.

Ідея в тому, щоб не тримати окремі файли інструкцій для кожного агента окремо.

Замість цього можна мати один уніфікований файл agents.md, який потенційно використовуватимуть різні AI-інструменти.

Уже зараз є багато інструментів, які починають підтримувати цей формат.

Створення agents.md через Codex CLI
Тепер повернемося до коду й використаємо Codex CLI, щоб автоматично створити agents-файл.

Автор уже перебуває в сесії Codex і запускає команду:

 
/init
 
Ця команда генерує новий файл:

 
agents.md
 
Коли ми використовуємо /init, Codex автоматично сканує кодову базу й створює файл із базовими правилами для проєкту.

Він може додати туди:

стилі кодування;
налаштування й підходи до тестування;
інформацію про структуру проєкту;
інші важливі речі, які знайде в кодовій базі.
Іноді Codex може додати також власні припущення або «особисті вподобання». Якщо ви таке побачите, варто їх трохи відкоригувати.

Під час створення файлу може знадобитися підтвердити виконання деяких команд.

Через кілька секунд Codex створює файл і розміщує його в корені проєкту.

Що містить створений файл
Після створення автор відкриває новий файл і бачить, що Codex написав досить повні інструкції.

Файл не надто великий, але його завжди можна доповнити пізніше.

У ньому є кілька розділів із різними заголовками.

Структура проєкту
Один із розділів описує структуру проєкту та організацію модулів.

Там пояснюється, де розташовані різні частини застосунку.

Наприклад:

папка app;
окремі route segments;
файл layout;
глобальний CSS-файл;
папка з reusable UI components.
Загалом цей розділ виглядає коректно й відповідає структурі поточного проєкту.

Команди для збірки, тестування та розробки
Далі у файлі є розділ із командами для:

збірки;
тестування;
запуску проєкту в режимі розробки.
Автор перевіряє ці команди й зазначає, що вони виглядають досить точними.

Стиль кодування та іменування
Також у файлі є розділ про стиль кодування та правила іменування.

Наприклад, Codex вказує використовувати PascalCase для певних назв.

Загалом це доволі типові правила, але вони сформовані на основі поточного стану проєкту.

Codex аналізує, як проєкт уже організований, і намагається вивести з цього загальні інструкції.

На цей момент усе виглядає досить точно.

Інструкції щодо тестування
У файлі також є розділ із рекомендаціями щодо тестування.

Codex згадує папку для тестів і пояснює, куди потрібно додавати тестові файли.

Це допомагає агенту в майбутньому правильно розміщувати нові тести й дотримуватися структури проєкту.

Інструкції щодо commit і pull request
У нижній частині файлу є рекомендації щодо:

commit-повідомлень;
роботи з pull request.
Це корисно, якщо ви хочете, щоб Codex не лише писав код, а й дотримувався певного стилю роботи з Git і GitHub.

Чому файл потрібно додати в GitHub
Автор зазначає, що файл agents.md бажано закомітити й відправити в GitHub-репозиторій.

Це важливо, якщо ви хочете, щоб Codex Cloud використовував цей файл під час виконання віддалених завдань.

Коли ви просите Codex щось зробити в хмарі, він автоматично шукає цей файл і використовує його як контекст для завдання.

Тому автор планує після запису відео відправити цей файл у GitHub, щоб усе було синхронізовано.

Чому agents.md потрібно оновлювати
Файл agents.md не варто створити один раз і забути про нього.

Коли ваш проєкт змінюється й розвивається, потрібно оновлювати й цей файл.

Наприклад, його варто редагувати, якщо:

ви почали використовувати нові бібліотеки;
ви додали новий фреймворк;
змінилася структура проєкту;
змінилися команди для тестування;
змінилися правила розробки.
Якщо файл не оновлювати, Codex може почати діяти за старими правилами, описаними в першій версії agents.md.

Через це він може відхилятися від актуального підходу до роботи в проєкті.

Підсумок уроку

Цей файл працює як інструкція для AI-агента: пояснює структуру проєкту, команди, стиль кодування, правила тестування та інші важливі особливості.

Codex використовує agents.md як контекст під час локальної роботи через CLI і під час віддалених завдань у Codex Cloud.

Тому файл варто додати до репозиторію й регулярно оновлювати разом із розвитком проєкту.
