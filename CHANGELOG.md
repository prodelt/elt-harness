# CHANGELOG

Все заметные изменения ELT. Формат — по фазам пересборки v5, потому что именно фазами она и
шла: каждая закрывала названный заранее критерий, а не «набор улучшений».

Текущие числа воспроизводимы командами из [README](README.md). Исторические значения явно
помечены как versioned snapshots и проверяются через `git show`, а не пересчитываются
скользящим окном сегодняшней даты.

## [5.0.0] — 2026-08-25

Граф стал рантаймом, а не схемой на бумаге. Маршрут `recon → plan → build → landing → mirror →
debrief → certified → publish` вычисляется из append-only журнала: `elt run` показывает узел и
следующий законный шаг, `elt advance` двигает прогон fail-closed, `elt cutover` переключает
авторитет с checkbox на журнал и не пишет ни байта, пока снимок миграции неоднозначен.

Что закрылось по существу:

- **Одна дверь вместо памяти.** Состояние восстанавливается другим процессом из журнала —
  это и есть resume после compact или падения фона. Низкоуровневые `oracle`/`judge`/`commit`
  остались диагностическим фасадом и пишут те же события.
- **Сертификат стал проверяемым.** Batch-сертификат выписывается из реальных терминалов
  оракула, пяти линз и оценщика, живёт вне дерева и требуется для `push` после смены эпохи.
  Схемы батча и релиза разные и невзаимозаменяемы.
- **Граница для внешних компонентов настоящая.** Узел pack'а исполняется только вне процесса,
  окружение собирается с нуля по белому списку (секреты хоста недоступны), все пять классов
  способностей запрещены по умолчанию, без обеспечиваемой границы узел `unavailable`.
- **Закрыта дыра доверенного пути гейта.** `ELT_GATE_TRUST_ORACLE` вычисляется из публичного
  файла, и раньше доверие снимало проверку дерева целиком. Теперь прощается ровно одна
  известная мутация — маркер `[X]`; посторонняя правка после зелёного оракула отвергается.

Что измерено и **не взято**, записано как есть: `ready→commit` p95 = 16,5 с при цели <5 с;
release-core 20 084 строки при цели ≤3 500 (graph-core уложился: 893 ≤ 1 500). A/B пилот на
трёх задачах чужого benchmark дал 3/3 против 3/3 — слишком лёгкие задачи, чтобы что-либо
различить. Наблюдательные пороги adoption и сигнал/шум имеют статус `not yet measured`.

## [5.0.0-rc] — 2026-08-24

Пересборка: харнес перестал быть движком на 32 тысячи строк со своей копией в `~/.claude/bin`
и стал плагином Claude Code, который ставится одной командой.

### Фаза 5 — релиз (спека 019, T016–T020)

- README отделяет сопоставимые KPI от исторических снимков и даёт `--as-of` для повторного
  среза; многорепозиторный результат считается суммой числителей и знаменателей, а не средним
  процентов.
- MIT-лицензия, этот CHANGELOG, открытый реестр известных дефектов и `.elt/ledger.jsonl` с
  порогом эскалации пять одинаковых сигналов.
- Приватный канонический репозиторий `prodelt/elt-harness`; D12 и D24 вынесены в GitHub Issues
  с меткой `harness-defect`. Тег `v5.0.0` ставится отдельным T020 после релизного коммита.

### Фаза 4 — плагин (спека 019, T011–T015)

- **Плагин `elt@elt`** со своим маркетплейсом. `bin/` — четыре точки входа: механический
  оракул, гейт L0, журнал дефектов, диагностика.
- **Инструкции живут в одном файле.** `AGENTS.md` и `.gemini/GEMINI.md` генерируются из
  `CLAUDE.md`; тест на дрейф краснеет на расхождении в одну строку. До этого три копии
  разошлись молча: `AGENTS.md` указывал на удалённый `tools/fleet/providers.js`,
  `.gemini/GEMINI.md` — на удалённый `tools/elt-loop.ps1`. Это и был корень жалобы
  «agy не читает скилы»: он читал — устаревший текст.
- **CI на двух платформах.** Замер перед вводом (WSL Ubuntu, node 24): из 76 файлов сьюта на
  Linux падал один, и тот только под `node --test`, а не под запуском оракула.
- **Deploy-копия снята.** `sync-bin.js`, побайтная сверка `tools/elt.js` с
  `~/.claude/bin/elt.js`, проверки `judge:bridge` и `harness:global-cli`, homedir-фолбэки в
  `elt.js`, `judge-core.js`, `checkpoint-writer.js` и путь в git-хуке `project-bootstrap`.
  Класс дефектов «правка есть в `tools/`, нет в копии» (D16, D18) закрыт архитектурно:
  установленный каталог и есть исходник.

### Фаза 3 — срезание (спека 019, T006–T010)

- Сняты `tools/fleet/**` (свой движок параллельности), PowerShell-драйверы, `approval-guard.js`,
  `sync-agent-surface.js`, codegraph-guard и 15 подсистем без единого вызова из живого пути.
  Каждый кандидат проверялся грепом на ссылки, а не по имени.
- Объём: 31 624 → 26 407 строк. **Цель ≤5 000 не взята** — остаток несущий, и путь к нему
  лежит через переписывание ядра, а не дальнейшее удаление.
- Ни один сценарий `PLAYBOOK.md` не потерян молча: у каждого либо замена штатным средством,
  либо явная запись «снято».

### Фаза 2 — ревью по официальному рецепту (спека 019, T001–T005)

- **Один список владения харнесом** (`tools/harness-files.js`). Два разошедшихся списка были
  общим корнем D9, D15 и D19 — харнес штрафовал за файлы, которые генерировал сам.
- **Батч-режим стал проходимым.** D13 (`.match()` без флага `g` — зона видела только первую
  задачу) и D14 (порог `diff-size` константой, без масштабирования на число задач).
- **Пять линз ревью** отдельными субагентами + оценщик уверенности на
  `claude-haiku-4-5-20251001`, отсечка 80.

### Фаза 1 — подпись спеки с критического пути (спека 018)
